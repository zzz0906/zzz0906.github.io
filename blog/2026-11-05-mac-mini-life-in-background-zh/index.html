    最近用了挺长一段时间 ChatGPT，我越来越觉得，Codex 的 CUA 能力特别好用。CUA，也就是 Computer Use Agent，可以直接操作电脑上的应用和网页：打开软件、查找资料、填写内容，再把几个步骤接起来做完。我人在外面、开车赶路的时候，电脑前的待办也不会停下来：EB-1A 的表格需要填写，员工培训的页面需要处理。我已经开始把这些资料整理、表单填写和界面操作交给 Codex，等它把结果准备好，再回来检查。

    这些经历让我突发奇想：我能不能买一台 Mac mini，把自己日常使用的软件都装上，让 ChatGPT 替我操作它们？ 工作消息来了，它去看；需要填写资料，它去找文件；有一项研发任务，它去调度其他 agent。ChatGPT 和 Mac mini 就像包在我外面的一层壳，替我接住生活中不断涌来的事情。我还在中间表达自己的想法，这层壳则负责把想法变成电脑上的具体动作。

    我用手机和 MacBook 通过 Remote Control 与 GPT 的主 agent 对话。Mac mini 运行日常 App 和 Loom，连接 GCP 服务与 GPU 集群，并用 OneDrive 同步资料。个人网站放在 GitHub Pages，外置硬盘负责 Time Machine 备份。点图可以放大。

    说干就干。第一步，先安装 OneDrive，让 Mac mini 有足够的信息。 我所有重要的文件，从论文、代码，到护照和各类个人资料，都按目录放在 OneDrive 下。填写一份表格，背后可能需要好几份材料；处理一个项目，也可能需要之前的文档和代码。如果每次都要我临时找文件、重新上传、解释背景，很多操作最后还是会绕回到我身上。所以我先把这些资料同步到 mini，让它能够沿着固定目录找到需要的内容。OneDrive 提供资料，项目对话保留上下文，后面的任务才能接着往下做。

    第二步，把日常会用的软件安装好。 Outlook 用来收发邮件，Slack 接住工作消息，短信和微信接住生活消息；Loom 是我用来操作 agent 的平台，Claude Code、Codex CLI 和 Cursor 负责研发；Word、PowerPoint 和 Chrome 处理文档、演示与各种网页。日历、Robinhood 等平时会打开的软件，也放进同一套环境。软件装好，自己的账号和工作目录准备好，Mac mini 就有了一个接近日常电脑的执行现场。这里说的“私人部署”，主要是把文件、软件和 agent 的执行环境放在自己的机器上，ChatGPT 的模型服务照常使用。

    Mac mini 常驻在那里，我则带着 MacBook 和手机出门。ChatGPT 提供 Remote Control 和 SSH 两种远程连接方式。Remote Control 可以接入 Mac mini 上运行的 ChatGPT 桌面版，继续原来的 Codex 对话。SSH 适合连接远程项目，跑命令、改代码。OpenAI 官方远程连接文档

    要让 Codex 用 CUA 操作 Mac mini 上的桌面 App，我一定选 Remote Control。 在我的配置里，用 SSH 连过去会限制 CUA。我也可以在手机上打开 Loom 查看任务进度。

    研发任务这一层，我用了自己制作的 Loom。它把 Claude Code、Codex、Cursor 等 coding agents 放进同一个控制台，让我和主 agent 能够看到有哪些项目、哪些任务正在运行，以及哪些结果需要处理。

    Loom 的组织方式很具体：先给每个 Project 建立目录，再在项目下面建立 task。每个研发 task 都有自己的终端、PLAN.md、Git 分支和 worktree。计划里记下目标与待办，agent 在自己的工作目录里修改代码、运行检查，产生的 diff 也归到这个任务下面。我可以同时推进几件事，再分别查看它们的改动；后续合并时，仍然要处理不同任务之间可能出现的冲突。

    Loom 的项目架构图，来自 GitHub README。点图可以放大查看。

    比如老板在 Slack 上交付一个需求，主 agent 先结合项目上下文理解要做什么，再通过 Loom 创建或找到相应的 task，调度子 agent 在各自的 worktree 里完成工作。任务的计划、终端、文件和改动都留在自己的位置。一个子 agent 在跑测试时，另一个可以继续处理别的任务；我需要了解进展时，也能回到对应任务里接着看。Loom 提供的 MCP 工具，让 Codex 能直接查询和调度这些任务。Mac、手机和网页上的入口，则连接同一个 Loom 服务端。

    需要 GPU 的研发任务，就从 Mac mini 连接 GPU 集群，部署到集群上执行。这样，日常软件和任务管理留在常驻的 mini 上，需要 GPU 的计算则交给集群。

    生活里的任务，主要依靠 CUA，加上少量 MCP。有直接工具接口的服务，就通过 MCP 连接；需要打开软件、查找页面、填写表单、整理文档的事情，就让 CUA 在 mini 上操作。律师发来一封需要补充资料的邮件，它可以先找相关文件、整理信息，再填写相应内容或准备回复。日历里的安排、聊天软件里的待办、需要处理的网页，也各自进入对应的任务。

    我直接和 GPT 的主 agent 沟通。 有新任务、要调整优先级，或对结果不满意，我就直接告诉它。它负责规划下一步、调用子 agent、跟进执行，再把结果带回来和我讨论。

    邮件就是很典型的例子。主 agent 可以先阅读上下文，拟好回复草稿。但我看到以后，可能会觉得口吻太正式、客套话太多，或者重点根本没有落在我想表达的地方。我就会告诉主 agent：“这封邮件重新写，直接一点，先回答对方的问题。”我们来回修改，直到内容和语气都更接近我自己。

    每一件事，都要分门别类地放好。 如下面的截图，签证材料、永居时间线、财产配置、保险、新公寓，以及论文宣传，分别保留在自己的任务里。它们有的正在执行，有的已经准备好结果，有的等待我补充信息。下次再有相关事情，我就回到原来的任务继续，沿用之前的材料和讨论。Loom 的常驻面板则让我看到哪些研发任务有新进展、需要我注意。

    任务保留各自的上下文，等待我随时调用，继续往下做。

    现在，我还不敢把对外回复和正式工作处理完全交给它。AI 的味道还是很重：一句话可能事实都对，但读起来就是不像我；有时写得很完整，却没有回答真正重要的问题。所以我会先和主 agent 沟通、修改，确认之后，由我自己点击发送按钮。

    但我相信，随着智能的上限不断提高，这一切都会改变。我想继续把这层壳搭起来，让它越来越了解我的资料、项目和表达方式，也越来越能把事情做到我想要的程度。现在它替我准备结果，我来做最后判断；以后，我希望自己只要说清楚想做什么，它就能替我处理更多事情。
