    November 5, 2026 中 #LLM Agent#Operating Systems

    我最近在尝试用一台 Mac mini 加上 ChatGPT，接管我生活里越来越多需要操作电脑的事情。第一步，是把 Mac mini 配成一台能够替我做事的电脑：我把日常会用的软件都安装好，让它拥有完整的工作和生活环境。OneDrive 负责存储我人生中所有重要的文件，工作资料、个人文档，以及处理各种事务时需要用到的材料，都有固定的位置。这样，当 agent 收到一件事，它能找到相应的软件和文件，继续往下做。Mac mini 是这套系统常驻的执行主机，MacBook 和手机则是我随身使用的本地设备。我带着它们出门，任务和工作环境留在 mini 上。

    第二步，是把所有对话分门别类地放进 Codex。我按生活和工作的主题管理项目，比如论文阅读、研发、财富、健康，以及各种长期推进的事情；每个项目对应 mini 上的实际目录，相关的对话也尽量归到同一个项目里。这样，一项任务做过什么、为什么这样做、接下来还缺什么，都可以在原来的上下文中继续。Codex 的跨设备访问能力，让我能够从不同设备接着管理这些事情：在 MacBook 上，我通过 SSH 连接 mini，在带有 macmini 标记的项目里继续聊天；在手机上，我选择同一台 Mac mini 作为远程主机，打开对应的项目和对话。迁移时，我还专门核对过两台 Mac 的十个项目，以及跨设备打开的消息和回复。这里有一个实际踩过的坑：聊天内容已经能读到，项目归属却可能没有同步跟上，所以后来又补了辅助同步。手机侧栏的名称和排序也可能与电脑不同，我会以实际连接的主机、项目目录和同一条对话为准。我的目标是，无论拿起哪台设备，都能接着管理同一套事情。

    研发任务这一层，我用一个叫 Loom 的工具组织子 agent。它能够在本地列出一份 agent 清单，让主 Codex 知道有哪些子 agent 可以调度，并把不同任务交给它们。具体流程是：先给每个 Project 建立目录，再在 Project 下面建立 task，每个 task 使用自己的 Git worktree。子 agent 进入对应的 worktree，围绕自己的任务修改代码、运行检查、整理结果。老板在 Slack 上交付一个需求后，主 agent 负责理解需求、结合项目上下文拆分工作，再通过 Loom 调度子 agent 去完成。每个任务都有自己的工作位置，我也能沿着 Project、task 和 worktree 找到它的进展与产出。这让多个研发任务可以同时推进，而我主要负责补充需求、判断优先级和查看结果。

    生活任务则主要依赖 CUA，加上少量 MCP。MCP 能直接连接的服务，就通过工具处理；更多需要打开软件、登录网页、查找信息和填写表单的事情，由 CUA 在 Mac mini 上操作。我把巡逻设为每十五分钟触发一次，让 Codex 检查日常使用的聊天软件和消息入口。Slack 上老板发来的需求、邮箱里需要处理的邮件、老婆发来的生活安排，都进入这套流程。比如律师来邮件要求填写资料，agent 就去找相关文件，整理需要的信息，再进入相应界面填写或准备回复。财富 agent 也按十五分钟的节奏查看股票和交易软件，执行我交代的操作。这些事情分别放在对应项目和任务里，方便我继续追问和检查。CUA 在这里很关键，因为生活中大量事情最后都要落到一个具体的软件界面上：找到按钮、填写内容、查看处理结果。Mac mini 提供了这个可以持续操作的环境。

    最后，我主要和一个主 agent 交谈，我把它当成自己的 chief of staff。它负责接住我的要求，协调不同的 agent，再把各项事情的进展汇总回来。我在 MacBook 或手机上打开同一条主对话，就可以补充想法、调整优先级，或者追问某件事做到哪里。偶尔我也会直接检查邮箱，看到 agent 已经准备好的草稿邮件，确认内容后就能发出回复。这个系统逐渐改变了我管理日常事务的方式：我把更多时间用来表达意图、做决定和看结果，具体执行留给 Mac mini 上的 agents。工作消息、邮件和生活安排陆续进来，mini 在后台继续处理，而我带着 MacBook 和手机，随时接着管理自己的生活。
