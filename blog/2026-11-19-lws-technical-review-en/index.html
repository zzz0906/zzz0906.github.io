    Mutable Inference: Making Learning Fit Between Predictions

    Review date: 2026-11-19
    Author: Zhongzhu Zhou
    Paper reviewed: Mutable Inference: Architecting LLM Accelerators for Inference-Time Learning
    Paper authors: Yimin Gao, Liangtao Dai, Melika Morsali, Junting Huo, Mircea Stan
    arXiv / DOI: 2611.18523 / 10.48550/arXiv.2611.18523
    Version and date: v1, 2026-11-13

    1. The question I think this paper answers

    An inference accelerator usually treats model weights as a stable input. A training accelerator expects backward propagation and weight updates between steps. Inference-time learning (ITL) breaks that division: the model predicts from a context chunk, learns from that chunk, and carries the updated weights into later predictions. The weights become part of the sequence state, alongside a bounded attention window.

    This is attractive for long contexts. Keeping every previous token in a KV cache makes storage and attention work grow with history. Learning can instead retain some context in mutable weights while attention sees a fixed window. But the learning computation has to run somewhere. A faster bounded-attention forward pass is not sufficient if each chunk must wait for a backward pass and weight update.

    I read this paper as an answer to a scheduling question with hardware consequences: which learning work must finish before a particular prediction uses a particular layer? The authors call their architecture Learning While Serving (LWS). Its three linked mechanisms are per-layer versioned weights, resumable matrix reductions, and specialized softmax-gradient datapaths. The first relaxes dependencies, the second turns fragmented spare time into usable computation, and the third removes a bottleneck that spare matrix capacity cannot solve.

    Figure 1. Original explanatory diagram based on paper Sections 2 and 4. The arrows represent dependencies and weight publication, not a promise that all work overlaps or that every chunk uses one globally consistent model version.

    The headline is carefully conditional. On modeled datacenter and edge NPUs, LWS reaches Prediction-only throughput for the principal workload. On TTT-E2E 3B at 128K context, the selected mixed-lag policy retains 99.34% of the fully fresh learning benefit measured in negative log-likelihood (NLL). That is neither 99.34% task accuracy nor learning at zero energy. The paper still reports additional learning energy, master weights, version storage, and substantial intermediate traffic.

    The strongest contribution, in my view, is the dependency decomposition. The evaluation supports a specific architecture under specific budgets. It does not establish that a current GPU can obtain the same gain through a runtime switch, or that multi-user decoding is solved. I distinguish paper-reported measurements, architectural simulation, and my own arithmetic throughout this review.

    2. Prerequisites: chunks, gradients, and mutable state

    The principal configuration is ITL(32,8): 32 Transformer layers, with the last eight MLPs mutable. Context is ingested in 1,024-token chunks, and attention uses an 8,192-token window. Prediction traverses all layers; Learning backpropagates through the mutable suffix. The frozen prefix of the next chunk can run before the previous chunk’s backward pass finishes. The first mutable layer is where freshness can become a barrier.

    For a linear map, let X∈RC×hX\in\mathbb{R}^{C\times h}X∈RC×h, W∈Rh×qW\in\mathbb{R}^{h\times q}W∈Rh×q, and Y=XWY=XWY=XW. Here CCC is the chunk token count. For upstream derivative G=∂L/∂YG=\partial\mathcal{L}/\partial YG=∂L/∂Y, taking the differential gives

    dL=tr⁡(G⊤dXW)+tr⁡(G⊤XdW).(1)d\mathcal{L}=\operatorname{tr}(G^\top dXW)+\operatorname{tr}(G^\top XdW). \tag{1}dL=tr(G⊤dXW)+tr(G⊤XdW).(1)

    Moving factors around the trace identifies the gradients:

    ∇XL=GW⊤,∇WL=X⊤G.(2)\nabla_X\mathcal{L}=GW^\top,\qquad \nabla_W\mathcal{L}=X^\top G. \tag{2}∇X​L=GW⊤,∇W​L=X⊤G.(2)

    Learning therefore adds matrix operations that can reuse inference MAC arrays. But backward work also includes nonlinear derivatives, reductions, activation reads, optimizer state, and weight writes. Counting only matrix FLOPs hides the hardware resources most likely to interfere with Prediction.

    There are three different notions of freshness. The forward pass reads an acquired quantized weight version. Backward propagation must retain that same version when computing derivatives associated with the forward computation. The optimizer applies the resulting gradient to the latest higher-precision master weights. These are separate responsibilities. Treating them as one mutable buffer either corrupts the derivative or forces a global barrier.

    For a tiny example, take y=xwy=xwy=xw and squared error L=12(xw−a)2\mathcal{L}=\tfrac12(xw-a)^2L=21​(xw−a)2. If the forward used w=1w=1w=1, x=2x=2x=2, and a=0a=0a=0, the upstream derivative is G=2G=2G=2 and the input derivative is Gw=2Gw=2Gw=2. Reading a newly published w=2w=2w=2 during backward would yield 4, which is not the derivative of that forward computation. This scalar example explains why a version reference must outlive the forward reader.

    The hardware need not keep every historic version forever. It needs to keep a version until its registered forward and backward uses finish. That lifecycle, rather than just an integer lag limit, determines whether an old bank can safely be overwritten.

    3. Layer order creates a freshness opportunity

    Prediction visits the mutable layers from input to output, M1 through M8. Backward propagation discovers their gradients in reverse order. M1 is needed earliest by the next forward pass but updated latest by the preceding backward pass. Uniformly demanding fully fresh weights puts the worst dependency exactly where Prediction first enters the mutable suffix.

    The paper tests policies whose digits specify additional visibility lag, relative to fully fresh execution. Policy 1111|0000 permits one extra chunk of lag for M1–M4 and none for M5–M8. It still updates every mutable layer on every chunk. Freezing M1–M4 is a different intervention that removes those updates entirely.

    Figure 2. Redrawn from paper Table 1. Quality experiments use fixed lag at the policy maximum; runtime acquisition can choose a newer published version. These are not measurements of a dynamic lag trace.

    At 128K, fully fresh learning reduces perplexity from 11.26 without updates to 10.87. Because NLL is the logarithm of perplexity, retention must be computed in log space. With P0P_0P0​ the no-learning perplexity, PfP_fPf​ the fresh-learning perplexity, and PpP_pPp​ the policy perplexity,

    Rp=ln⁡P0−ln⁡Ppln⁡P0−ln⁡Pf,Pp=P0exp⁡[−Rpln⁡(P0/Pf)].(3)R_p=\frac{\ln P_0-\ln P_p}{\ln P_0-\ln P_f},\qquad P_p=P_0\exp[-R_p\ln(P_0/P_f)]. \tag{3}Rp​=lnP0​−lnPf​lnP0​−lnPp​​,Pp​=P0​exp[−Rp​ln(P0​/Pf​)].(3)

    The reference NLL improvement is approximately ln⁡(11.26/10.87)=0.03525\ln(11.26/10.87)=0.03525ln(11.26/10.87)=0.03525. Inserting 0.9934 gives an illustrative implied perplexity of about 10.873, using the paper’s rounded endpoints. This is my arithmetic, not an extra reported measurement. The missing 0.66% applies to the improvement, not to the entire NLL.

    Table 1 reports 99.34% retention for 1111|0000, 96.29% for uniform lag one, 98.57% for 2111|1000, and 76.23% when the input half is frozen. The mixed policy’s mean lag is only 0.5 chunks. Its advantage is consistent with dependency order, but mean lag alone cannot predict quality: different layers have different sensitivity, and the learning trajectory changes over time.

    I would not extrapolate the retention percentage to arbitrary tasks. It comes from 16 Books3 validation sequences. The absolute benefit is small enough that confidence intervals, document composition, and rounding matter. Preserving that benefit is valuable; it remains a narrower result than preserving every capability of a full-context model.

    4. Capacity is a vector, and idle time has a shape

    The motivating AWS Inferentia2 profile has tensor-engine activity for 27% of a TTT-E2E forward layer under default materialized attention. A TPU v5e profile achieves 19% of peak matrix throughput. These observations motivate looking for unused capacity, but they are not interchangeable utilization statistics: engine-active time and achieved peak throughput use different denominators.

    Figure 3. Redrawn from paper Figure 4 and its text. The text specifies 33% for matrix demand, while the original figure rounds its label to 0.3. The bars refer to idealized demand relative to available idle capacity, not measured final utilization.

    For each resource rrr, let PrP_rPr​ and LrL_rLr​ be Prediction and Learning demand over a Prediction-only chunk period, and KrK_rKr​ the capacity during that period. A necessary aggregate condition for full throughput is

    Pr+Lr≤Krfor every resource r.(4)P_r+L_r\le K_r\quad\text{for every resource }r. \tag{4}Pr​+Lr​≤Kr​for every resource r.(4)

    A matrix-only test passes: Learning needs about one third of idle matrix capacity. The vector ALU test fails: its Learning demand is 2.1 times idle capacity. Removing the two softmax-gradient operations from accounting lowers this to about 0.3. Removing attention-gradient work alone leaves 0.8, and removing vocabulary-gradient work alone leaves 1.5. The two gradients account for 86.8% of Learning vector work.

    Even satisfying (4) does not prove schedulability. A six-unit matrix job cannot fit into three two-unit idle intervals if it cannot be interrupted. It can fit if it saves progress at legal boundaries and pays small enough suspension overhead. Dependencies and deadlines introduce a second condition: the capacity must occur after operands become ready and before the weight version is needed.

    An interval form makes that distinction explicit. For Learning tasks whose entire legal execution window lies in interval III, their required service cannot exceed the idle service available in that interval:

    ∑j: [aj,dj]⊆Iej≤∫Icidle(t) dt.(5)\sum_{j:\,[a_j,d_j]\subseteq I} e_j\le \int_I c_{\mathrm{idle}}(t)\,dt. \tag{5}j:[aj​,dj​]⊆I∑​ej​≤∫I​cidle​(t)dt.(5)

    This is my necessary scheduling test, not a theorem claimed by the paper. Precedence constraints, memory contention, and nonpreemptible blocks can make it insufficient. Its practical value is to explain why a global utilization percentage is a weak admission rule. A workload can have spare matrix cycles overall and still miss the earliest mutable-layer deadline.

    5. Architecture: share the arrays, specialize the obstacles

    The modeled datacenter NPU has TPU v5e-class budgets: 393 INT8 TOPS, 819 GB/s HBM bandwidth, and 16 GiB memory. LWS organizes compute into 145 groups, four MAC clusters per group, and 16 MXINT8 MAC tiles per cluster. This gives 580 independently schedulable clusters. Only eight groups contain dedicated softmax-gradient units, Stash Q, and a Learning Engine slice.

    Figure 4. Cropped from the original diagram without altering its scientific content. The Learning Engine, version control, and specialized units cooperate with existing memory and matrix datapaths.

    Prediction uses the Control & Issue path and retains priority. Learning tasks become ready as dependencies finish. The Issue Arbiter dispatches tiles to available clusters; the Prefetch Queue requests operands through DMA. A request from Prediction causes a Learning tile to yield at a reduction boundary. The Weight Update Engine applies completed gradients to master weights and quantizes the new compute-format version before publication.

    The phrase “without another MAC array” needs care. LWS does not add a duplicate training array, but it is not an unchanged TPU v5e. Its matrix budget is reorganized into many smaller schedulable clusters instead of four large MXUs. That organization is part of the proposal. The paper compares sharing mechanisms on a common underlying NPU budget, which is useful for mechanism isolation; direct speed claims about commercial TPU software would need another comparison.

    Why not a fixed training partition? It makes progress predictable but withholds resources from Prediction when Learning has nothing ready. Why not lend entire engines? An engine assigned to a fused attention operator can contain unusable gaps at a finer granularity than the lending interface exposes. Why not interleave complete instructions? A long instruction still blocks reclamation until it finishes. LWS changes the granularity at which computation can be borrowed and returned.

    The specialized units solve another tradeoff. Building backward support everywhere would add area and forward-path complexity. Centralizing the expensive preparation in eight equipped groups amortizes that hardware, at the possible cost of traffic and bottlenecks at those groups. A larger or differently structured learning workload could require a different number of equipped groups; the paper’s eight-group choice is an evaluated operating point, not a universal constant.

    6. Weight versions: acquisition, publication, reclamation

    Each mutable layer has quantized weight banks in DRAM and a Version Table containing version tags, the current bank, and reader counts. Prediction acquires the newest published version that meets its allowed lag. If none is fresh enough, it waits. A bank cannot be recycled merely because it is no longer current: backward computation may still need it.

    Figure 5. Original state-flow diagram based on paper Section 4.2 and Figure 6. Three banks illustrate lag two. The real safety condition is completion of all registered readers, not passage of a fixed amount of wall time.

    Algorithm 1. Acquire a layer version and publish an update

    This numbered pseudocode is my logical rendering of the paper’s mechanisms. It is not quoted code. vmin⁡v_{\min}vmin​ is the minimum version allowed by the current layer’s freshness requirement.

    1. Acquire(layer, v_min): wait until current.tag >= v_min.
2. Atomically read current bank/tag and pin its forward use.
3. If backward will use this weight, also pin that use now.
4. Return the immutable bank/tag token to the computation.
5. Release each registered use only when that use finishes.
6. PublishUpdate(layer, gradient): serialize master updates.
7. If lag = 0, wait for zero readers and reuse its sole bank.
8. Else claim a noncurrent bank with zero readers, or wait.
9. Update the high-precision master; quantize into the bank.
10. After all writes complete, atomically publish the new tag.

    The separate pins in steps 2–3 matter. If the forward pin were released before a backward reference existed, publication could reclaim the bank during the gap. The descriptor for a suspended Learning tile also records its weight version, so resumption cannot silently switch to a newer version. Version consistency links the scheduler to memory safety.

    The authors provision ℓ+1\ell+1ℓ+1 banks for a layer with permitted lag ℓ\ellℓ and report that this avoids allocation stalls in the evaluated workload. I read this as an empirical provisioning result. A lag limit bounds version age; it does not by itself bound the number or lifetime of arbitrary concurrent readers. A different pipeline, batched requests, or a slow backward consumer could keep a bank pinned longer.

    Publication also requires a real ordering rule. The current pointer can change only after the destination bank is completely written. Otherwise a reader can observe a valid tag with partial weights. The paper describes fully written publication; a production design would need explicit memory-ordering and fault semantics around that operation.

    7. Consistent derivatives still permit stale optimization

    Let W^t,l\widehat W_{t,l}Wt,l​ be the quantized version layer lll acquired for chunk ttt, and Mt,lM_{t,l}Mt,l​ the latest master weights when its update is applied. The learning rule is schematically

    gt,l=∇WlLt(W^t,1,…,W^t,L),Mt+1,l=Mt,l−αgt,l.(6)g_{t,l}=\nabla_{W_l}\mathcal{L}_t(\widehat W_{t,1},\ldots,\widehat W_{t,L}),\qquad M_{t+1,l}=M_{t,l}-\alpha g_{t,l}. \tag{6}gt,l​=∇Wl​​Lt​(Wt,1​,…,Wt,L​),Mt+1,l​=Mt,l​−αgt,l​.(6)

    The gradient belongs to the acquired forward computation but is applied to a more recent master. Keeping forward and backward versions consistent prevents one class of error. It does not make (6) identical to fresh SGD. LWS explicitly trades visibility delay for a schedule with more overlap, and its quality experiments test that tradeoff.

    For a scalar quadratic f(w)=12aw2f(w)=\tfrac12aw^2f(w)=21​aw2, a one-step delayed gradient gives wt+1=wt−αawt−1w_{t+1}=w_t-\alpha a w_{t-1}wt+1​=wt​−αawt−1​. Looking for solutions wt=ztw_t=z^twt​=zt yields

    z2−z+αa=0.(7)z^2-z+\alpha a=0. \tag{7}z2−z+αa=0.(7)

    For this illustrative recurrence, stability requires 0<αa<10<\alpha a<10<αa<1, whereas fresh scalar gradient descent permits 0<αa<20<\alpha a<20<αa<2. This is not a convergence model for TTT-E2E. It demonstrates why a bounded version lag can still change optimization stability and why the learning rate and lag policy should be evaluated together.

    Higher-precision master weights have a different role. If repeated small updates are rounded directly into low-precision compute weights, each update can vanish below the quantization step. Keeping a master lets the increments accumulate before publishing a rounded version. The paper versions only compute-format banks; master updates remain sequential. This reduces storage relative to versioning every optimizer tensor, but readers and the update engine still share DRAM bandwidth.

    The same distinction helps interpret 1111|0000. It is a vector of layerwise visibility permissions, not one global checkpoint index. A Prediction can combine layer versions with different ages. The resulting computation is well-defined, but its semantic distance from a fresh model cannot be summarized by a single average lag.

    8. Resumable reductions preserve useful partial work

    LWS divides each Learning tile’s reduction dimension into 32-element blocks, matching the microscaling block size. Prediction may reclaim a cluster after the current block finishes and the pipeline drains. The controller stores 256 B of partial sums per suspended tile and a 46-bit descriptor, supporting eight suspended tiles per cluster with 2 KB of local SRAM.

    Figure 6. Original illustrative schedule. Green work resumes from its saved reduction index after blue Prediction work; durations are schematic and are not simulator results.

    For one output entry of a matrix product, split KKK into blocks BbB_bBb​:

    Cij=∑k=0K−1AikBkj=∑b(∑k∈BbAikBkj).(8)C_{ij}=\sum_{k=0}^{K-1}A_{ik}B_{kj}=\sum_b\left(\sum_{k\in B_b}A_{ik}B_{kj}\right). \tag{8}Cij​=k=0∑K−1​Aik​Bkj​=b∑​(k∈Bb​∑​Aik​Bkj​).(8)

    Saving the running accumulator and next block index avoids replaying completed products. It also avoids saving arbitrary in-flight pipeline state. Numerical equivalence still depends on preserving accumulation precision, scales, and reduction order; mathematical associativity alone does not guarantee bitwise equivalence in finite precision.

    Algorithm 2. Suspend and resume a Learning tile

    1. Dispatch a ready tile only after Prediction drains its tile.
2. Load its pinned weight version, operands, and block index b.
3. Accumulate the next 32-element reduction block.
4. Advance b only after its products reach the accumulator.
5. If Prediction requests the cluster, drain the pipeline.
6. Save partial sums and the descriptor; restore Prediction scales.
7. Yield the cluster without releasing the weight-version pin.
8. On a later grant, restore accumulator, descriptor, and operands.
9. Resume at b; on tile completion, publish outputs and release uses.

    The hardware diagram labels a group stall of at most eight cycles. That is a local arbitration property, not an end-to-end request-latency bound. DMA queues, SRAM conflicts, vector readiness, and weight freshness can still delay useful work. The reported throughput result incorporates the simulator’s contention model; a real latency distribution would need separate validation.

    There is also a granularity tradeoff. Short blocks reduce reclamation delay but create more control and state traffic. Long blocks amortize overhead but miss narrow gaps. Choosing 32 aligns suspension with MX arithmetic, making a safe boundary cheap to describe. It does not imply that a software kernel can reproduce the mechanism without hardware changes.

    9. Attention softmax gradients: derive the specialized work

    For one attention row with scores sss, let pj=exp⁡(sj)/∑kexp⁡(sk)p_j=\exp(s_j)/\sum_k\exp(s_k)pj​=exp(sj​)/∑k​exp(sk​) and let gj=∂L/∂pjg_j=\partial\mathcal{L}/\partial p_jgj​=∂L/∂pj​. Differentiating the normalized exponential gives the Jacobian ∂pj/∂si=pj(1[i=j]−pi)\partial p_j/\partial s_i=p_j(\mathbf1[i=j]-p_i)∂pj​/∂si​=pj​(1[i=j]−pi​). Multiplying by ggg gives

    ∂L∂si=pi(gi−∑jpjgj).(9)\frac{\partial\mathcal{L}}{\partial s_i}=p_i\left(g_i-\sum_j p_jg_j\right). \tag{9}∂si​∂L​=pi​(gi​−j∑​pj​gj​).(9)

    The reduction scalar can be recovered from the attention output. With O=∑jpjVjO=\sum_j p_jV_jO=∑j​pj​Vj​ and upstream dOdOdO, we have gj=Vj⊤dOg_j=V_j^\top dOgj​=Vj⊤​dO, so

    r=∑jpjgj=(∑jpjVj)⊤dO=O⊤dO.(10)r=\sum_jp_jg_j=\left(\sum_jp_jV_j\right)^\top dO=O^\top dO. \tag{10}r=j∑​pj​gj​=(j∑​pj​Vj​)⊤dO=O⊤dO.(10)

    This avoids a separate reduction over every attention position, following the FlashAttention-2 identity cited in the paper. It does not eliminate the elementwise products in (9), which remain enough to create vector contention.

    Figure 7. Original numerical example, not a paper experiment. For p=(0.2,0.3,0.5)p=(0.2,0.3,0.5)p=(0.2,0.3,0.5) and g=(1,−1,2)g=(1,-1,2)g=(1,−1,2), r=0.9r=0.9r=0.9 and dS=(0.02,−0.57,0.55)dS=(0.02,-0.57,0.55)dS=(0.02,−0.57,0.55), whose sum is zero.

    LWS stores unnormalized attention probabilities P′P'P′ and normalization metadata during Prediction. Its dS unit adjusts them to the final row bound, combines them with dP and rrr, and emits unnormalized score gradients. The remaining normalization is deferred into dQ and dK. Unlike recomputation-based backward attention, this choice spends storage and bandwidth to avoid recomputing probabilities.

    For explanation, if pi=ui/Zp_i=u_i/Zpi​=ui​/Z in a consistent row scale, then dSi=ui(gi−r)/ZdS_i=u_i(g_i-r)/ZdSi​=ui​(gi​−r)/Z. The common row factor can be applied later in matrix products that form dQ and dK. A tiled implementation must also align each tile’s running maximum with the final maximum. The paper’s datapath handles that exponent adjustment; dropping it would change the gradient.

    Why specialize these operations? A vector ALU has to serve both Prediction and Learning. Offloading the dominant backward softmax path lets Learning’s matrix work proceed without making the forward softmax wait. The alternative is to recompute or use generic vector hardware, each with a different mix of bandwidth, compute, and contention. The best choice can change when attention windows, memory bandwidth, or the number of concurrent sequences changes.

    10. Vocabulary gradients and two-pass normalization

    For logits zzz, softmax probabilities ppp, and target vocabulary index aaa, cross entropy is L=−za+log⁡∑iexp⁡zi\mathcal{L}=-z_a+\log\sum_i\exp z_iL=−za​+log∑i​expzi​. Differentiating the target term and the log-sum-exp gives

    ∂L∂zi=pi−1[i=a].(11)\frac{\partial\mathcal{L}}{\partial z_i}=p_i-\mathbf1[i=a]. \tag{11}∂zi​∂L​=pi​−1[i=a].(11)

    The dZ unit evaluates this without materializing a vocabulary-sized probability array. A first streaming pass collects a stable normalizer; a second pass regenerates logits, produces probabilities, and subtracts the target indicator. Sharing exponent hardware between passes saves area but requires the logits or their inputs to be available again.

    For natural-exponential notation, when a block with local maximum mbm_bmb​ and local exponential sum SbS_bSb​ arrives, the running pair (m,S)(m,S)(m,S) updates as

    m′=max⁡(m,mb),S′=Sexp⁡(m−m′)+Sbexp⁡(mb−m′).(12)m'=\max(m,m_b),\qquad S'=S\exp(m-m')+S_b\exp(m_b-m'). \tag{12}m′=max(m,mb​),S′=Sexp(m−m′)+Sb​exp(mb​−m′).(12)

    This rescales old and new sums into one common exponent range. The second pass uses pi=exp⁡(zi−m)/Sp_i=\exp(z_i-m)/Spi​=exp(zi​−m)/S. The paper’s hardware uses base-two exponent and logarithm operations; (12) expresses the same normalization principle in familiar notation and is not a literal datapath specification.

    Algorithm 3. Two-pass vocabulary gradient

    1. Initialize running maximum m = -infinity and sum S = 0.
2. Stream blocks of logits; compute each block maximum and sum.
3. Merge each block into (m, S) using stable rescaling.
4. Finish pass one; retain only normalization metadata.
5. Stream the logits a second time in the same token context.
6. Compute probability from the final normalizer.
7. Subtract one at the target index; emit gradient blocks.
8. Release metadata after the downstream consumer completes.

    This is another example of a dataflow choice rather than a new learning objective. Vocabulary projection, attention gradients, and matrix backpropagation must meet as one dependency graph. A faster isolated dZ unit is useful only if it relieves the critical shared resource and feeds subsequent matrix work in time. The paper’s demand analysis motivates that placement rather than assuming every custom unit automatically improves throughput.

    Stash preparation follows the same principle. Prediction stores activations in their original BF16 layout. Learning later gathers and quantizes them into 32-token blocks for X⊤GX^\top GX⊤G. This keeps expensive gather/quantization hardware out of every forward cluster. It also makes the activation stash part of the memory budget; quantized compute weights alone do not describe ITL’s footprint.

    11. What was measured, simulated, and compared

    The main quality workload is TTT-E2E 3B on Books3 validation at 32K, 64K, and 128K context. Quality retention uses 16 input sequences. The policy experiments use a BF16 reference; the modeled accelerator uses MXINT8 matrix arithmetic with higher-precision updates. The authors report less than 0.001 additional NLL in their end-to-end TTT-E2E 3B 128K validation versus BF16. That arithmetic check is useful but is not a broad precision study across all workloads.

    Architectural performance comes from a unified operation-level simulator. It models dependencies and contention across MAC, vector, SFU, SRAM, and DRAM resources. Matrix latency and preemption overhead derive from RTL simulations. Ramulator 2 supplies DRAM completion events; DRAMPower and characterized SRAM macros support energy estimates. Logic synthesis uses 16 nm technology at 1 GHz, and an equipped compute group is placed to assess feasibility. This is stronger than a FLOP-only estimate, while remaining distinct from a fabricated chip measurement.

    The authors map the TTT-E2E Learning workload onto eight additional model architectures, giving nine-model throughput results. Those eight models are not all demonstrated to have been trained into equivalent ITL models with matching quality. The mapping tests the hardware workload across shapes and sizes. LaCT and online LoRA supply additional learning mechanisms, with different dependency structures.

    The baselines share the modeled resource budget but keep their original sharing mechanisms. Serial completes Prediction and Learning before the next chunk. DaCapo uses a static split. Neu10 lends engines. Equinox interleaves instructions. The latter three use a previous model copy to permit whole-model lag one, whereas LWS can impose layer-specific visibility requirements. Consequently, the comparison mixes scheduling capability with freshness policy; the throughput–quality plot is needed alongside a raw speed bar.

    The evaluation concerns one long-context sequence during chunked prefill. Batched serving and autoregressive decoding are explicitly outside scope. I therefore interpret “Prediction throughput” as prompt-processing throughput within this setting, not users served per second or a token-by-token streaming latency guarantee.

Those are smaller than the nine-model headline comparisons. This is not a contradiction: the model subset and averaging differ. Using 1.6 as the principal model’s directly measured gain would be inaccurate.

    LaCT is informative because its updates are local to layers. LWS reaches full throughput with fully fresh weights and retains 100% of its learning benefit at 32K. Equinox also reaches full throughput in that comparison but uses lag one and retains 92.8%. LWS’s value is therefore sometimes better freshness at equal throughput, not simply a larger speed number.

    13. Ablations and the area denominator

    Figure 9. Redrawn from paper Figure 11(a). Its serial point is 0.69 for the principal workload; the nine-model serial average in Table 2 is 0.64. These two denominators should not be merged.

    Removing dS/dZ units lowers normalized throughput to 0.87. Removing resume support lowers it to 0.74. Requiring fully fresh weights lowers it to 0.84. These interventions show that each mechanism matters. Their penalties cannot be added to predict a design missing all three, because bottlenecks shift and the same delay can be exposed by multiple constraints.

    The resource accounting makes that interaction concrete. Prediction-only MAC activity is 49.5% in the modeled principal workload, and LWS adds 31.0 percentage points of Learning activity, leaving 19.5% without active MAC computation. This realized Learning occupancy is greater than the ideal matrix demand from Figure 4 because opportunistic sharing and interruptions cost time. Dedicated softmax units restrict extra shared-vector occupancy to 3.5% of the chunk period.

    Area has two valid but different denominators. Table 3 reports baseline compute logic of 44.41 mm² and added LWS logic of 1.47 mm², about 3.3%. Including SRAM in the core-area denominator gives 1.5%. The edge equivalents are 4.3% for compute logic and 2.7% for core area. A standard group grows about 2%, while an equipped group grows about 23%.

    The largest individual dedicated contribution is dS/dZ at about 0.30 mm² across eight groups. Resume controllers appear small per cluster but are replicated 580 times. For scale, 580 clusters times 2 KB of partial-sum storage is roughly 1.13 MiB, before descriptors and other buffers. This is a simple capacity calculation, not a new area estimate; SRAM macro area and distributed control determine actual cost.

    The 1.5% headline is meaningful within the synthesized core model. It excludes the inference that an existing commercial die could be modified for that fraction of total engineering cost. Timing closure, verification, packaging, compiler work, and manufacturing are different quantities that the paper does not price.

    14. Memory traffic and the throughput roofline

    The principal model’s quantized weights occupy about 3.0 GB. Versioning adds 178 MB, and the higher-precision master weights for eight mutable MLPs add 1.04 GB, bringing weight storage to roughly 4.2 GB. The master copy is required by serial ITL as well as LWS. Comparing LWS only against static inference would assign this shared ITL cost to the wrong mechanism.

    The paper accounts for 8.5 GB of attention-probability traffic and 2.43 GB of master-weight, residual-state, and version-publication traffic per chunk. These are traffic totals, not quantities that all remain resident simultaneously. Conversely, the 4.2 GB weight footprint is not the whole working set: KV state, activations, gradients, and buffers still matter.

    As a rough consistency check, 1,024 tokens at 7,046 tokens/s take about 0.1453 seconds. Dividing the cited 10.93 GB traffic by that interval gives about 75.2 GB/s. This is not measured bandwidth utilization: it includes only the two listed traffic categories and ignores other traffic, burst timing, and channel contention. It merely shows why a large per-chunk byte count can coexist with a large nominal bandwidth budget.

    15. Limitations I would keep in view

    The quality evidence is concentrated on one primary model, a small validation sample, and long-context language modeling. There are no sequence-level confidence intervals for the reported retention table. A high retained fraction can coexist with document-specific failures; entity retrieval, chronology, and rare details could react differently to stale weights.

    The performance setting is deliberately narrow. A single sequence during chunked prefill does not capture interleaved user arrivals, variable chunk boundaries, decode deadlines, cancellation, or per-user mutable state. These can change both spare capacity and the lifetime of pinned versions. The result should motivate serving research rather than stand in for a production serving benchmark.

    The full-throughput result is architectural simulation supported by RTL and physical estimates. It is not a fabricated chip. The paper provides a structured model of contention, but unmodeled timing or compiler constraints can alter overlap. Its comparison against reexpressed prior mechanisms is controlled, yet original systems may offer different optimizations in their native settings.

    The attention-probability stash is a substantial design choice. It substitutes bandwidth and memory state for recomputation. If the attention window grows, memory resources shrink, or many sequences overlap, its value can reverse. Likewise, eight specialized groups can become a hot spot under a different balance of vocabulary size and attention work.

    Finally, fixed lag quality is not identical to adaptive runtime quality. The reference experiments use each policy’s maximum lag, while runtime acquisition chooses the newest acceptable published version. Variable lag might help by being fresher, but a mixed temporal pattern can also change optimization. The reported tests do not establish a monotonic relationship between lag and downstream behavior.

    16. Critical analysis: what I would test next

    16.1 Separate a visibility policy from a quality guarantee

    The paper’s best insight is to make freshness a per-layer contract. Its weakest extrapolation would be to treat one empirically good lag vector as an architecture-independent contract. A hardware deadline states when an update becomes available; a quality contract states what harm is acceptable. These require different validation.

    I would collect the actual per-layer acquired-version trace and replay it in the BF16 reference, then compare it with fixed-maximum-lag and fully fresh runs on the same documents. Report document-level paired NLL differences, confidence intervals, and tails. This would directly connect the simulated schedule to quality without assuming a constant lag pattern. It would also reveal whether rare publication stalls, rather than typical lag, dominate failures.

    16.2 Test whether the idle windows survive a stronger forward path

    LWS explicitly supports tiled attention, and the paper recognizes that tiling fragments idle time. Still, the opportunity depends on how effective Prediction is. Better fused forward kernels, different matrix/vector ratios, or batching may consume the headroom the learner borrows. I would compare at least two optimized forward schedules and show both idle-capacity volume and idle-window distributions, then use the same learning graph on each.

    A useful outcome would be a breakdown of missed deadlines: insufficient aggregate capacity, operands arriving too late, unavailable version bank, and preemption overhead. A single throughput curve does not tell an accelerator designer which knob to change. Capacity fractions from different profiles should remain separate rather than being combined into a synthetic utilization estimate.

    16.3 Evaluate bank provisioning under an adversarial reader

    The ℓ+1\ell+1ℓ+1 bank rule works for the evaluated pipeline. I would add a controlled delay to one backward consumer while allowing later work to progress, then measure bank-allocation stalls and retained state. This tests the exact safety condition the version table enforces. It does not require assuming the bank rule is wrong; it identifies the concurrency envelope in which it is enough.

    For batched serving, the right abstraction might be one mutable context per sequence plus shared frozen weights. Memory should then be reported per active sequence and as a function of maximum outstanding backward work. Cancellation must release forward pins without releasing still-needed backward pins, and recovery must not publish half-written banks. These are concrete extensions to the architecture’s lifecycle contract.

    16.4 Compare probability stashing with recomputation fairly

    The custom dS path spends 8.5 GB of attention-probability traffic per chunk in the principal setup. An alternative could recompute probabilities using spare MAC capacity but save DRAM traffic. I would compare total energy and deadline misses under bandwidth throttling, not only isolated kernel latency. The decision should include stash quantization error and the extra time it keeps activations alive.

    The common objective is a constrained schedule: maximize Prediction throughput subject to quality, memory, and energy limits. One illustrative formulation is

    max⁡ℓ, b, uηs.t.ΔNLL≤ϵ, M≤Mmax⁡, E≤Emax⁡.(15)\max_{\boldsymbol\ell,\,b,\,u}\eta\quad\text{s.t.}\quad \Delta\mathrm{NLL}\le\epsilon,\ M\le M_{\max},\ E\le E_{\max}. \tag{15}ℓ,b,umax​ηs.t.ΔNLL≤ϵ, M≤Mmax​, E≤Emax​.(15)

    Here ℓ\boldsymbol\ellℓ is the lag vector, bbb the suspension granularity, and uuu the choice of specialized or recomputed gradient path. This is my proposed design framing. The paper explores parts of this space but does not solve this general optimization. Making the constraints explicit prevents a 1.00 throughput point from masking unacceptable memory cost on edge hardware.

    16.5 Strengthen baseline and statistical reporting

    The paper reports useful common-budget comparisons. I would additionally request a freshness-matched baseline and a hardware-matched baseline with the same cluster organization but no LWS mechanisms. This would separate gains due to per-layer policy, finer matrix partitioning, and specialized backward hardware. The existing ablations help, but each changes the bottleneck and may not isolate all interactions.

    For the 16-document quality sample, use paired document resampling rather than treating every token as independent. The retained fraction divides by a small fresh-learning benefit, so it can be noisy. Report absolute NLL, perplexity, and retention together, and identify any documents for which the denominator is near zero or negative. This is an actionable reporting improvement, not evidence that the current mean is incorrect.

    My overall assessment remains positive: this is a coherent hardware argument built around a real semantic distinction. Its practical reach would be much clearer with actual schedule replay, memory-pressure stress tests, and a broader quality sample. Those additions target the paper’s specific inferential gaps rather than asking for unrelated benchmarks.

    17. Reading checks and a reproducible evaluation plan

    I read the complete 14-page v1 PDF, including its references; this version has no separate appendix. I checked derivative identities and recalculated the ratios, NLL-retention conversion, memory arithmetic, and roofline example. The examples and analytic curves here are explanatory; I did not train models or reproduce accelerator performance.

    An independent study should fix the model, documents, tokenization, chunk length, window, mutable layers, optimizer, and precision. Compare no learning, fresh learning, fixed lag, and schedule replay on identical documents, recording actual acquired versions and preserving forward/backward consistency.

    Architectural comparisons should retain the same forward graph and resource budgets, expose bank lifetimes and missed deadlines, and separate warm-up and drain from steady state. Short prompts may be dominated by those boundary costs.

    18. Conclusion

    LWS shows how a new dependency contract can unlock old hardware capacity. Selected layers tolerate delayed visibility, resumable reduction blocks make fragmented idle time useful, and dedicated softmax-gradient units prevent vector work from blocking the overlap. Together, these mechanisms achieve the modeled principal operating point with nearly all fresh-learning NLL benefit and Prediction-only throughput.

    The result I would carry forward is conditional and useful: when learning work fits in the resource and deadline envelope, hardware can hide its latency without adding a second matrix array. Energy, memory, quality uncertainty, and serving concurrency remain separate constraints. Treating them explicitly makes this paper a stronger starting point for systems design.
