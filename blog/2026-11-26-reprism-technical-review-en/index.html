    RePrism: Joint Scheduling of Requests and Prompt Representations

    Review date: 2026-11-26 (UTC)
    Author: Zhongzhu Zhou
    Paper reviewed: RePrism: Joint Request and Representation Scheduling for LLM Agent Serving
    Paper authors: Xijiang Shen, Aoli Zhu, Yanbo Tan, Xiyuan Hu, Huailiang Tan
    arXiv: 2611.32545
    Version and date: v1, 2026-11-24

    1. What I take away from RePrism

    RePrism changes the object that a serving scheduler compares. Instead of choosing a ready LLM call and only afterward deciding how to execute its reusable prompt, it compares pairs: a request and one eligible representation. That representation can be an explicit prompt, a prefix KV cache, a previously trained LoRA adapter that internalizes a fixed prompt, or an adapter combined with cached residual context. The resulting choice affects current latency, future reuse, and the memory available to other calls. These effects make a purely request-first order incomplete [1, Sections 1–4].

    My main interest is the connection between semantic permission and systems optimization. The adapter paths are useful only after the application accepts an approximation to the behavior of a prompt. Direct and KV are treated as exact execution paths; Adapter and Hybrid need not produce the same token sequence. A cache hit and a qualified behavioral substitute therefore carry different contracts. The scheduler cannot turn an unqualified substitute into an eligible one merely because it is fast.

    The paper demonstrates the complete system on one RTX 3090 with Llama-2-7B-Chat. At a dynamic arrival rate of 1.8 sessions/s it reports 1.37 times S-LoRA’s request throughput and a 4.10-fold reduction in P95 session completion time. The more focused comparison with request-first scoring reports 2.7% higher throughput and 12.3% lower mean session completion time. These results answer different questions: the first combines representation availability, scheduling, and cache policy, while the second isolates a narrower scheduling decision [1, Sections 5.2 and 5.5.2].

    Figure 1: Original explanatory Mermaid diagram based on Sections 4 and Appendix A. Offline qualification determines permission; online scoring and admission determine what runs.

    This review follows the complete 19-page v1 PDF, including Appendices A–C. I distinguish paper measurements, independently checked arithmetic, and constructed examples. I have not trained the adapters or rerun the serving benchmarks. The most useful open questions are how reliably behavioral qualification transfers, how output-length error changes memory safety, and whether the CPU scheduling cost remains worthwhile with many candidates.

    2. Prerequisites: a session is a graph, and a prompt has lifetimes

    A session is one user task implemented by several dependent calls. Let its visible workflow be a directed acyclic graph with nodes representing calls or execution stages and edges representing data or control dependencies. A node is ready only after its required predecessors finish and its branch condition holds. A serving scheduler can reorder ready nodes; it cannot execute through a dependency. A fork can expose parallel work, and a join cannot complete until its required branches finish.

    For a session arriving at time a and completing its target node at time f, session completion time is f minus a. Time to first token measures a different interval, from submission of an individual request to its first token. Improving the TTFT of a noncritical branch can leave the session’s finishing time unchanged. Conversely, moving a small join-unblocking call ahead of a large independent call may improve SCT even without accelerating either call’s kernels.

    The paper decomposes a request into fixed behavior P, reusable residual context R, and call-specific input Q:

    x=P∥R∥Q.(1)x=P\mathbin\Vert R\mathbin\Vert Q. \tag{1}x=P∥R∥Q.(1)

    P can be a stable role instruction or output schema reused across sessions. R contains session or path state and is more likely to be reused by successors within a session. Q is the new query. These are logical reuse scopes, not permission to treat arbitrary equal-length strings as equal context. Exact KV reuse requires a matching effective model and prefix, including ordering and positional interpretation.

    For an ordinary decoder, prefill constructs attention keys and values for the input; decoding then extends those states token by token. Caching the input avoids repeated prefill but leaves the corresponding tokens visible to subsequent attention. An adapter can remove P from the online token sequence, yet adds low-rank operations and changes the model. For a weight matrix, LoRA writes an update as

    W′=W+BA,B∈Rdout×r,A∈Rr×din.(2)W'=W+BA,\qquad B\in\mathbb R^{d_{out}\times r},\quad A\in\mathbb R^{r\times d_{in}}. \tag{2}W′=W+BA,B∈Rdout​×r,A∈Rr×din​.(2)

    The update uses r times the sum of the input and output dimensions parameters, rather than their product. Its size depends on rank and adapted layers, not directly on prompt length. This is a storage observation, not a proof that a given rank can encode every prompt of a given length. The semantic complexity of the instructions and the base model’s capabilities also matter.

    I find the decomposition most useful as an interface between the application and the serving system. The application exposes reusable identities, dependency information, and allowable substitutes. The serving system uses these facts to estimate costs. If it has only input lengths and timestamps, it cannot reconstruct all of these relationships; the paper explicitly identifies this limitation of public production traces.

    3. Four representations, four different resource plans

    Direct processes P, R, and Q as text and releases its reusable cache after the request. KV retains the states of a matching prefix so that only the suffix needs new prefill. Adapter replaces the explicit fixed prompt P with trained weights and prefills R and Q. Hybrid uses the same adapter plus residual KV states computed for R under that adapter; on a hit, only Q needs new prefill [1, Section 2].

    Figure 2: Original explanatory table derived from Section 2. Hit-path inputs are shown; missing state still has to be loaded or built.

    The warm path makes KV attractive for first-token latency. In the longest tested configuration of paper Figure 4, KV occupies 1000 MiB, Adapter 64 MiB, and Hybrid 192 MiB. The associated TTFT speedups relative to Direct are approximately 6.70, 3.26, and 6.62. Yet the end-to-end speedup peaks at only about 1.18 across the measured settings because output generation remains substantial. The prompt lengths shown on the plot include chat-template tokens, so I do not substitute the four raw fixed-prompt lengths from the qualification experiment for the plotted lengths.

    Figure 3: Paper Figure 4, cropped without changing the plotted data, from PDF page 4. TTFT acceleration and end-to-end acceleration have different denominators.

    Hybrid’s residual cache is not free. At residual lengths of 64, 128, 256, and 512 tokens, the paper reports first-build-and-register costs of 25.28, 37.33, 65.47, and 140.79 ms. Subsequent hits save 29.77, 33.69, 70.18, and 120.25 ms relative to Adapter. Ignoring eviction and opportunity costs, the number of future hits needed to repay the build is obtained from

    n ΔThit≥Tbuild,nmin=⌈Tbuild/ΔThit⌉.(3)n\,\Delta T_{hit}\ge T_{build},\qquad n_{min}=\left\lceil T_{build}/\Delta T_{hit}\right\rceil. \tag{3}nΔThit​≥Tbuild​,nmin​=⌈Tbuild​/ΔThit​⌉.(3)

    The four ratios are about 0.85, 1.11, 0.93, and 1.17: one, two, one, and two future hits, respectively. This calculation explains why reuse can pay quickly, but it does not justify keeping every residual forever. A cache occupying scarce memory can delay other requests or cause a more valuable object to be rebuilt. Offline adapter training also lies outside these online build costs.

    Two alternatives remain sensible. Always using Adapter saves residual storage when R rarely repeats. Always using Hybrid maximizes repeated-residual benefit when reuse is strong and memory is available. RePrism matters in the intermediate regime where those conditions differ across requests or change over time.

    4. Behavioral qualification is an eligibility gate

    The paper illustrates internalization using the Schema-Guided Dialogue Media_1 state-tracking task. A fixed prompt defines output fields and state-update rules; R supplies the previous state, and Q supplies a new utterance. The base weights remain fixed while attention-layer LoRA parameters are trained against ground-truth target answers. Although the explicit-prompt configuration motivates a teacher/student interpretation, Appendix B describes target-answer prediction-error training; I do not infer an unreported token-level teacher KL objective.

    The example uses 48 training examples, 12 development examples, and a separate 24-example qualification set. Evaluation is greedy with a maximum of 64 generated tokens. An output must contain all five fields and satisfy intent and field-value checks. Field ordering can differ from Direct. The threshold is 0.85; ranks 4 and 8 fail for the 1004-token Media_1 prompt, while rank 16 reaches 0.917 and qualifies. The lowest passing rank is selected, subject to a rank ceiling [1, Section 3.1 and Appendix B].

    The qualification score is a finite-sample pass fraction:

    B^=1n∑i=1n1{check⁡(yi)=1},B^≥0.85.(4)\widehat B=\frac1n\sum_{i=1}^{n}\mathbf 1\{\operatorname{check}(y_i)=1\},\qquad \widehat B\ge0.85. \tag{4}B=n1​i=1∑n​1{check(yi​)=1},B≥0.85.(4)

    This is an operational admission rule for a representation. It is not an assurance that every future session meets the same probability, nor that all possible user instructions are preserved. Appendix C makes the intended behavior concrete: the new request enables subtitles, the intent stays PlayMovie, the title Body Double is carried from the prior state, and irrelevant director and genre fields become NONE. A plausible-looking answer with the wrong title or a wrong genre fails even if its formatting is correct.

    RePrism separates this semantic permission from cache residency. A qualified Hybrid path remains eligible when its residual cache is absent if the cache can be rebuilt. Conversely, a resident cache cannot make an unqualified adapter eligible. Even identical residual text cannot directly reuse KV computed under a different adapter. In a deployed interface I would bind a residual-cache identity to the model, adapter, effective prefix, and positional configuration; this is a correctness consequence of model-dependent KV, not a new mechanism measured by the paper.

    The later scheduling experiments use proxy adapters with the same tensor structures but different weights. The paper compares one qualified rank-16 adapter to its proxy and finds differences below 1.3% in mean throughput and mean P95 SCT. That supports a performance surrogate in the tested setting. It does not establish behavioral correctness for all proxy adapters or all scheduled sessions. I return to this distinction in the critical analysis.

    5. Deriving the node and representation scores

    The ready set contains dependency-satisfied calls. For each call v, the application supplies eligible modes M(v). A readiness-and-eligibility indicator filters the pair space:

    Ct={(v,m):v∈Rt, m∈M(v), Et(v,m)=1}.(5)\mathcal C_t=\{(v,m):v\in\mathcal R_t,\ m\in\mathcal M(v),\ E_t(v,m)=1\}. \tag{5}Ct​={(v,m):v∈Rt​, m∈M(v), Et​(v,m)=1}.(5)

    The scheduler scores node progress and representation benefit separately, normalizes each to [0.5, 1], and multiplies them. Appendix A.1 estimates a remaining critical-path length L_v by adding a node’s Direct execution-time estimate to the largest remaining path among its successors. For running nodes, the estimate scales with remaining output budget; nodes not yet at the server also include known tool wait. The longest remaining visible session path is L_s. With H equal to 60 seconds,

    Pt(s,v)=HH+LsLvLs,Wt(s)=min⁡(1,ws/H).(6)P_t(s,v)=\frac{H}{H+L_s}\frac{L_v}{L_s},\qquad W_t(s)=\min(1,w_s/H). \tag{6}Pt​(s,v)=H+Ls​H​Ls​Lv​​,Wt​(s)=min(1,ws​/H).(6)

    The first factor favors sessions nearer completion; the second favors their critical branches. The waiting accumulator increases only while the session has a ready request and no running request. Time spent executing or waiting on parallel branches does not automatically create extra urgency. This is more specific than simply using wall-clock session age.

    With both node weights set to one, node value is P plus W. Representation value combines immediate benefit, discounted future reuse, and resource opportunity cost, also with unit weights:

    Vnode=P+W,Vrepr=Vnow+Greuse−Oresource.(7)V^{node}=P+W,\qquad V^{repr}=V^{now}+G^{reuse}-O^{resource}. \tag{7}Vnode=P+W,Vrepr=Vnow+Greuse−Oresource.(7)

    Let T_D and T_m include prefill and decoding under Direct and mode m. Let the incremental preparation cost be the difference between resource plans before and after adding the candidate. The immediate benefit follows by subtracting execution and preparation from the Direct reference time, then dividing by that reference:

    Vnow(v,m)=TD−Tm−ΔTloadTD.(8)V^{now}(v,m)=\frac{T_D-T_m-\Delta T_{load}}{T_D}. \tag{8}Vnow(v,m)=TD​TD​−Tm​−ΔTload​​.(8)

    A warm hit can be attractive; a cold adapter or residual build can make this term negative. For example, Direct 100 ms, mode execution 30 ms, and new loading 20 ms yield 0.5. Loading 90 ms instead gives -0.2. These are explanatory numbers, not RePrism measurements. Counting the full load of an adapter already needed by the tentative batch would overcharge the new candidate; the paper therefore uses incremental preparation.

    6. Future reuse, opportunity cost, and joint ordering

    The future term considers pending visible requests, excluding the current request and requests already selected in the round. Each future saving is weighted by execution probability p_u and discounted by dependency delay d_u, using T_0 equal to one second:

    Greuse(v,m)=1TD∑upuΔTu1+du/T0.(9)G^{reuse}(v,m)=\frac1{T_D}\sum_u\frac{p_u\Delta T_u}{1+d_u/T_0}. \tag{9}Greuse(v,m)=TD​1​u∑​1+du​/T0​pu​ΔTu​​.(9)

    Already-submitted requests have probability one; remaining conditional nodes use known branch probabilities. If a future request could reuse several resources, its total saving is distributed across those resources. Otherwise the same saved prefill could be credited multiple times. For a constructed example with T_D of 100 ms, a 40-ms saving, probability 0.5, and a one-second delay, the contribution is 0.1. Increasing the delay to nine seconds lowers it to 0.02. Thus the score values near-term reuse, not just an undifferentiated count of descendants.

    The opportunity term estimates the change in rebuild costs of potential eviction victims before and after adding the candidate. It divides this difference by T_D and clips it to [-1, 1]. A negative value is possible when the changed plan reduces restoration cost; it should not automatically be clamped to zero. These estimates are derived from offline profiling and runtime residency, rather than a claim of clairvoyant future knowledge.

    Finally, the joint score is

    St(s,v,m)=N[0.5,1](Vnode) N[0.5,1](Vrepr).(10)S_t(s,v,m)=N_{[0.5,1]}(V^{node})\,N_{[0.5,1]}(V^{repr}). \tag{10}St​(s,v,m)=N[0.5,1]​(Vnode)N[0.5,1]​(Vrepr).(10)

    After normalization each component can alter its own factor by at most two. The product lies in [0.25, 1]. This bounded range tempers domination by one component; it does not make the result an optimal SCT policy or prove starvation freedom. The paper supplies the target normalization range but does not fully specify every degenerate normalization case. A concrete implementation must define what happens when all raw values tie or when a candidate set contains one pair. I leave those details unspecified in the paper-derived pseudocode.

    Figure 4: Original numerical illustration. A has node value 1 but representation value 0.5; B has node value 0.75 and representation value 1. Joint ranking chooses B before A.

    In the illustration, request-first scoring fixes A before considering mode costs. Joint scoring obtains 0.50 for A and 0.75 for B. This is the basic motivation, but only feasible pairs may compete. A score cannot authorize reuse of another adapter’s KV, exceed the dynamic memory reserve, or bypass a required predecessor. The scheduler also gives requests waiting more than 60 seconds precedence, still subject to dependencies and resources. The two uses of 60 seconds, a score time scale and an override threshold, should be kept conceptually separate.

    7. Algorithms: select tentatively, admit atomically

    The paper’s Algorithm 1 updates workflow and resource state, constructs feasible pairs, scores them, and sorts them once at the start of the round. Once the first feasible pair for a request enters the plan, the other modes of that same request are skipped. Admission is projected as the plan grows, but no eviction is committed during candidate selection. The ranking remains fixed within the round [1, Section 4.3].

    Algorithm 1: Joint pair selection

    The following numbered pseudocode restates the paper’s scheduling logic at an explanatory level. The normalization and cost estimators remain the paper’s abstract operations.

    1. Update visible DAG, running batch, and resource state.
2. Collect calls whose dependencies and branches are ready.
3. Pair each call with its behaviorally eligible modes.
4. Remove hard-infeasible pairs; compute joint scores.
5. Sort once, applying the overdue-request precedence.
6. Start an empty tentative plan.
7. Visit each pair in order:
   a. Skip if its call already appears in the plan.
   b. Project merged-batch memory without eviction.
   c. If feasible, append the pair and update the projection.
   d. Stop if the batch is full.
8. If nonempty, atomically admit the plan (Algorithm 2).
9. Otherwise consider prefetch only at an idle safe point.
10. Return the plan, or no plan if admission fails.

    The bypass in step 7 matters. A high-priority candidate that cannot fit does not prevent smaller feasible candidates farther down the order from using the GPU. This improves utilization but complicates fairness: an oversized or resource-conflicted request may keep being bypassed despite high priority. The 60-second precedence is still resource-constrained, so it is not a hard service-time bound.

    Algorithm 2: Batch resource admission and eviction

    The second algorithm is the boundary between a proposed decision and actual shared-resource changes. The union operation must count a resource referenced by several calls only once.

    1. Form the union of resources required by the plan.
2. Project peak dynamic KV for running and new requests.
3. Reject if the merged requirement is hard-infeasible.
4. Compute the extra bytes that admission needs.
5. Protect resources held by running calls, being loaded,
   or required by the tentative plan.
6. Rank other resident resources by retention value/byte.
7. Select enough victims; prune unnecessary excess victims.
8. If the victims cannot free enough bytes, reject unchanged.
9. Atomically reserve memory and commit those evictions.
10. Return success and the committed victim set.

    Projecting and committing separately prevents a failed batch attempt from partially evicting resources or leaving inconsistent reservations. The paper describes the atomic reservation abstraction; it does not offer a formal concurrent correctness proof. The prose around ProjectAdmit also deserves care: it says tentative checks do not evict resident resources, while CommitAdmission later decides victims. I interpret the former as a projection without destructive side effects, and preserve both stages rather than replacing them with an invented implementation.

    Prefetch is available only when no batch runs and the waiting queue is empty. This path was not triggered in the reported experiments. It therefore cannot explain the measured improvements, and should not be described as an experimentally demonstrated source of gain.

    8. Deriving the peak-memory check

    The Resource Manager divides the runtime budget between reusable objects and dynamic KV storage. Base weights and fixed workspaces are outside this runtime partition. Shared reusable objects count once, and the dynamic reserve must cover the projected merged batch:

    Mkeep+Mnew+bKVTpeak≤Bruntime.(11)M_{keep}+M_{new}+b_{KV}T_{peak}\le B_{runtime}. \tag{11}Mkeep​+Mnew​+bKV​Tpeak​≤Bruntime​.(11)

    For a standard attention model with L layers, h_KV KV heads, head width d, and b bytes per scalar, storing both K and V for one token requires

    bKV=2LhKVdb.(12)b_{KV}=2Lh_{KV}db. \tag{12}bKV​=2LhKV​db.(12)

    The paper’s Llama-2 setup uses 0.5 MiB per token. Its 16000 token-equivalent budget is therefore 8000 MiB. Helium is given 14000 equivalents, or 7000 MiB, to account for different static framework use under the common 22000-MiB whole-GPU cap, with 3% runtime variation. The distinction matters: the experiments do not give every framework identical runtime-token capacity. They attempt to align total peak memory use.

    Appendix A.3 improves on simply adding per-request maxima. Sort requests by remaining output budgets in descending order, o_1 at least o_2 and so on. Let u_i be dynamic tokens already held by request i. Just before the kth-longest request finishes, the first k requests remain, each has generated o_k additional tokens, and shorter requests have released their dynamic state. The occupancy at that event is the sum of their u_i plus k times o_k. Thus

    Tdecode=max⁡1≤k≤n(∑i=1kui+kok).(13)T_{decode}=\max_{1\le k\le n}\left(\sum_{i=1}^{k}u_i+k o_k\right). \tag{13}Tdecode​=1≤k≤nmax​(i=1∑k​ui​+kok​).(13)

    This derivation assumes the synchronous decode progression and release behavior underlying the estimator. It does not automatically cover arbitrary asynchronous execution, unexpected output lengths, or additional speculative state. The system also checks prefill memory; decoding alone is not the complete batch requirement.

    Figure 5: Original example derived from paper Equation A4. Held tokens are (10, 40, 50), remaining outputs are (30, 10, 5), and completed requests release state.

    In this example the three event values are 40, 70, and 115 tokens. Current occupancy is 100, so using current memory alone underestimates the future peak by 15. Adding all individual peaks gives 145, an overly conservative value because their maxima occur at different times. At 0.5 MiB/token, these values are 50, 57.5, and 72.5 MiB. These are mathematical illustrations, not a new GPU measurement.

    A practical consequence follows from the word expected in output budget. If an output forecast is only a statistical expectation, it is not a strict upper bound. A production adaptation needs an enforced generation cap, an uncertainty reserve, or a runtime response to overrun. RePrism’s formula is useful under its assumptions; claiming universal OOM prevention would go beyond the paper.

    9. Retention value and the economics of eviction

    An eviction policy should compare the value of keeping a byte, not only recency. RePrism’s score for resource i is

    Di=CiBi(1+ri)(1+min⁡(4,hi)4).(14)D_i=\frac{C_i}{B_i}(1+r_i)\left(1+\frac{\min(4,h_i)}4\right). \tag{14}Di​=Bi​Ci​​(1+ri​)(1+4min(4,hi​)​).(14)

    C_i is the profiled restoration time saved by keeping the object; B_i is its size. The future-demand estimate r_i lies in [0, 1] and uses the current candidate ranking. The history count h_i tracks rebuilds within 10 seconds after eviction, retaining rebuild records for 60 seconds. The two multipliers each lie between one and two, so together they can increase the base density by at most four.

    For an illustrative adapter costing 20 ms to reload and occupying 40 MiB, the base density is 0.5 ms/MiB. With r equal to one and at least four recent rebuild events, its score becomes 2. A 100-MiB KV object costing 60 ms to rebuild but with no demand or rebuild bonus has density 0.6. Recency-independent scoring would retain the adapter more strongly in this constructed state. This is reasonable if the demand estimate is useful, but incorrect forecasts can preserve stale objects.

    The manager first accumulates low-density victims until it frees enough space. It then revisits selected victims from higher to lower retention value and removes any whose eviction is unnecessary. This reduces excessive eviction caused by indivisible variable-size objects. It does not solve the optimal subset problem. For example, needing 6 MiB with low-density candidates of 4 and 4 MiB followed by a slightly higher-density 6-MiB object can lead the greedy pass to select 8 MiB; neither selected 4-MiB object can then be removed. The 6-MiB alternative remains unselected. This is a limitation of a heuristic, not evidence of a defect in the measured system.

    Evicted adapters are offloaded to CPU memory and can be reloaded. Evicted KV is discarded and recomputed because rebuilding was cheaper than CPU-to-GPU transfer under the test conditions. That conclusion is hardware- and workload-dependent; it does not imply that recomputation always beats transfer on other systems. Running, loading, and plan-required resources remain protected even if their density is low.

    10. What the experiments actually compare

    The main platform is a single 24-GB RTX 3090, with Llama-2-7B-Chat, 128 GB host memory, and an Intel 8171M CPU configured with 52 logical cores. RePrism is built on S-LoRA. S-LoRA and Chameleon provide Direct/Adapter paths without DAG access; SGLang provides Direct/KV without DAG access; Helium provides Direct/KV with workflow information; RePrism combines all four representations with DAG information [1, Table 1]. Those differences are part of the full-system comparison, so the largest speedups cannot be attributed solely to the product score.

    Dynamic workloads mix CI repair, incident response, and multi-document analysis. Session arrivals follow a Poisson process at 0.7–1.9 sessions/s for 200 seconds, after which the run drains. The client limits in-flight requests to 128, retaining additional ready requests locally. Adapter assignment follows a Zipf distribution with exponent 1.1. These are designed workloads with explicit reuse and dependencies; they are not a reconstructed production trace.

    Figure 6: Paper Figure 8, cropped without changing data, from PDF page 9. Helium has no per-request first-token timestamp, so its TTFT curve is absent.

    Throughput is completed requests divided by the entire sending-and-draining interval. SCT starts at a session’s scheduled arrival; TTFT starts when a request reaches the client submission interface. Therefore TTFT can exclude earlier waiting in the client’s local ready queue. A system that moves waiting between client and server can change request TTFT without an equally large change in user-perceived session time. Reporting SCT alongside it is essential.

    At 1.8 sessions/s the paper reports roughly 14 requests/s for RePrism and a 1.37 throughput ratio over S-LoRA, plus the 4.10-fold P95 SCT reduction. A reduction by a factor of 4.10 corresponds to about 75.6% lower latency, not a 410% decrease. At 1.7 sessions/s, the P50 TTFT reduction factors are 9.40 against S-LoRA and 18.01 against SGLang. These are P50 dynamic-load observations; the 5.26 mean-TTFT factor comes from a separate controlled experiment.

    The controlled workload contains 96 sessions and 1056 requests, using the CI-repair template. Policy comparisons use gamma interarrival times with shape 0.5 and a target rate of 0.2 sessions/s. Default P, R, Q, and output lengths are 1152, 256, 256, and 128 tokens, with 32 rank-16 adapters. Resource-pressure tests release sessions together. Results are averaged over five runs, which improves stability but does not substitute for raw dispersion or confidence intervals for every reported ratio.

    11. Ablations reveal where adaptation helps

    Request-first RF uses the same node score, backend, representation ranking, and resource-management policy; RF-FIFO orders by arrival instead. This is the more informative comparison for the joint decision itself. Across tested residual and query lengths, throughput gains are at most 5%. At R and Q both 256, mean-SCT reduction factors are 1.35 versus RF-FIFO and 1.14 versus RF. The paper’s coverage experiment reports the more precise 12.3% mean-SCT reduction and 2.7% throughput increase at 50% eligibility. Rounded factors and percentages are compatible but should not be treated as identical exact numbers.

    Removing representation options also matters. Direct-only RP-D has 27% lower throughput than S-LoRA. Adding either Adapter or KV approaches the baseline, while allowing Direct, Adapter, and KV exceeds it and cuts mean SCT by more than a factor of two. The complete system’s 5.26-fold mean-TTFT reduction demonstrates the benefit of a broader execution menu and reuse, not a 5.26-fold benefit of joint scoring alone.

    Reuse conditionFixed Adapter SCTFixed Hybrid SCTRePrism SCT

    Adapter wins in Cold; Hybrid wins in Hot. RePrism is about 5.24% and 3.69% above the best fixed choice in the corresponding workload. This is a good adaptation result, but it is not dominance over an oracle choosing the best fixed strategy with knowledge of the workload. In Hot, always using Adapter costs about 24.4% extra SCT relative to fixed Hybrid; in Cold, always using Hybrid costs about 9.35% extra relative to fixed Adapter.

    The eviction comparison gives mean SCT of 82.5, 85.6, 129.9, and 196.5 seconds for RePrism, RP-LRU, immediate-discard RP-SE, and S-LoRA. Mean TTFT is 2.5, 2.8, 6.3, and 13.2 seconds. These rounded plot labels imply a modest further gain over LRU and a larger gain from retaining reusable objects at all. Ratios recomputed from one-decimal labels need not exactly match ratios computed from the underlying unrounded data.

    12. Coverage, visibility, and CPU cost define the boundary

    The coverage parameter q is the fraction of distinct prompts eligible for adapter-based modes, not the fraction of requests or tokens. With Zipf-distributed use, a 50% prompt coverage can cover much more or much less than half the traffic depending on which prompts qualify. Increasing q from zero to one raises RePrism’s throughput from 1.56 to 2.16 requests/s and lowers mean SCT from 206.85 to 51.87 seconds. These are about 38.5% more throughput and 74.9% lower SCT in that experiment.

    The incremental benefit of joint scoring is largest with mixed eligibility. At q equal to one, its mean-SCT gain over RF is at most 1%; at zero it is slightly worse than RF. This pattern supports the paper’s motivation: the joint choice is most consequential when execution options differ across ready calls. It also counsels against presenting the product score as universally superior.

    Figure 8: Redrawn from explicit values in Sections 5.5.2 and 5.5.3. The panels are separate controlled experiments; their absolute values should not be combined into one factorial result.

    Full visibility exposes complete submitted workflows; Next-hop exposes ready calls and their successors; Frontier exposes only ready calls. Dependencies are still enforced using the complete graph in all three. Thus the Frontier result tests reduced scheduling information, not autonomous reconstruction of unknown dependencies. Full-to-Frontier changes throughput from 1.97 to 1.89 requests/s and SCT from 82.48 to 108.09 seconds: about 4.1% less throughput and 31.0% higher mean SCT. The scheduler retains a smaller advantage over request-first policies at each visibility level.

    Cross-model tests report throughput ratios of 1.10, 1.30, and 1.31 for Llama-2, Llama-3-8B-Instruct, and Qwen-2.5-7B-Instruct, with a mean-SCT factor of 1.32 on each. Runtime budgets differ by model to maintain the total cap: 8000, 5875, and 5687.5 MiB. These results broaden the evidence beyond one architecture, while remaining single-GPU experiments with model-dependent memory and KV geometry.

    Figure 9: Selected measured points from Appendix A.4, redrawn. Lines only connect those points; no intermediate measurements are invented.

    One ready call has four candidates. Median CPU tick latency rises from 1.01 ms at four candidates to 17.19 ms at 128 and 62.45 ms at 512; P95 and P99 at 512 are 64.21 and 65.64 ms. These queue-populated microbenchmarks use one-node sessions and measure the CPU routine, not a universal GPU-idle interval. Nevertheless, 62 ms is large next to short calls. Whether it overlaps execution or becomes a scheduling bottleneck must be measured rather than assumed.

    13. Limitations and what can be independently checked

    The evidence combines a small semantic demonstration with broader performance experiments using shape-matched proxy adapters. A successful surrogate timing comparison at rank 16 is useful, but does not establish that every prompt, model, rank, and generated workflow output keeps the same behavioral validity. The study’s semantic admission threshold is an application requirement, not a claim that exact prefix caching and prompt internalization are interchangeable.

    The workload generator controls dependencies, prompt-to-adapter mapping, lengths, reuse, and branch information. That makes ablation possible and limits external validity. Real agent executions may have evolving graphs, variable tool delays, prompt edits, and branch probabilities that drift with model outputs. In particular, substituting an approximate adapter can change generated residual text and subsequent branches; the performance surrogate workload does not demonstrate the resulting closed-loop semantic and systems effects together.

    The tests use one GPU. Extending the same policy to tensor parallelism, pipeline parallelism, disaggregated prefill/decode, or a cluster introduces replica locality, transfer, communication, and consistency costs. The paper names multi-GPU extension as possible; it does not measure those extensions. Offline adapter preparation, invalidation after prompt or model updates, and qualification maintenance also need an amortization ledger beyond online cache-build costs.

    The score uses profiled execution times, output budgets, and branch probabilities. Its result depends on forecast quality and candidate-set normalization. The memory projection assumes a particular decode model, and the urgency rule cannot serve a hard-infeasible call. No formal optimality or latency-bound claim follows from these heuristics. This does not diminish the measured result; it defines its scope.

    For independent reading checks, I recomputed the cache break-even ratios, unit conversions, normalized-score example, peak-KV event maxima, Table 2 excess costs, and percentage/factor conversions. These checks validate arithmetic and interpretation, not serving performance. A future experimental reproduction would need the exact generated workload, arrival sequence, length conventions, eligibility mapping, whole-GPU cap, runtime budgets, request-release rules, drain interval, and metric timestamps. I do not claim such a reproduction here.

    14. Critical analysis: qualify the optimization target

    The most consequential weakness is uncertainty in behavioral admission. The reported 0.917 is consistent with 22 passes out of 24 qualification cases. For independent Bernoulli trials, a standard Wilson interval is

    B^+z2/(2n) ± zB^(1−B^)/n+z2/(4n2)1+z2/n,z=1.96.(15)\frac{\widehat B+z^2/(2n)\ \pm\ z\sqrt{\widehat B(1-\widehat B)/n+z^2/(4n^2)}}{1+z^2/n},\qquad z=1.96. \tag{15}1+z2/nB+z2/(2n) ± zB(1−B)/n+z2/(4n2)​​,z=1.96.(15)

    With 22/24, its approximate 95% interval is [0.742, 0.977]. This calculation does not refute the observed pass rate. It shows that a point estimate above 0.85 is not strong evidence that the unknown population rate exceeds 0.85. Searching ranks against the same qualification set can introduce additional selection optimism; the simple interval does not correct for that adaptive search.

    I would separate rank development from a final locked qualification set, stratify failures by rule type and residual novelty, and admit approximate paths only when the application’s chosen lower confidence bound clears its requirement. A very strict application may retain Direct/KV throughout; another may explicitly accept a bounded approximation. Reporting a speedup at a stated acceptance contract is more meaningful than calling every eligible path equivalent.

    A second improvement is to measure quality-adjusted session goodput. Let N be completed sessions, pass_s indicate a final behavior check, and slo_s indicate completion within the chosen deadline. Over total observation time T, a proposed evaluation metric is

    Gvalid=1T∑s=1N1{passs}1{slos}.(16)G_{valid}=\frac1T\sum_{s=1}^{N}\mathbf 1\{pass_s\}\mathbf 1\{slo_s\}. \tag{16}Gvalid​=T1​s=1∑N​1{passs​}1{slos​}.(16)

    This is my suggested measurement, not a paper result. It would count complete valid sessions per second and expose cases where an approximate fast path changes downstream outputs or causes retries. Useful controls would preserve semantic task inputs, record real generated residuals and branches, and report both exact-only and qualification-constrained modes. A workload with fixed proxy outputs cannot resolve this question alone.

    Third, I would perturb the cost and length forecasts deliberately. Sweep calibration error for T_m, output budgets, tool waits, and branch probabilities; report OOM recovery, bypassed-request age, cache churn, SCT tails, and wasted work. Memory reservation should use an explicit bound or calibrated quantile, with a documented fallback when actual outputs exceed prediction. A heuristic tested only at a well-calibrated operating point can look much more robust than it is.

    Finally, candidate pruning and bounded scheduling work deserve evaluation. The reported overhead suggests testing a fixed CPU-time budget, per-request dominated-mode elimination, cached score components, and recalculation only when relevant state changes. Such changes could reduce policy quality or accidentally freeze stale estimates; their worth should be assessed through valid session goodput, not CPU time alone. Joint scheduling is a useful interface, and the next step is to make its semantic and prediction costs visible in the objective.

    15. Conclusion

    RePrism makes prompt representation part of online scheduling and connects that decision to workflow progress and shared GPU state. Its strongest lesson is the coupling: whether to run a call now depends partly on which representation it can use, while the representation’s value depends partly on which other calls will run soon. The paper gives a concrete joint score, a memory projection, and atomic admission and eviction procedures to act on that coupling.

    The measurements support a practical benefit on designed single-GPU workloads, especially with mixed representation eligibility and useful visible reuse. They also show boundaries: a best fixed representation can win in a homogeneous regime, joint scoring adds much less than the full-system speedup, and CPU candidate evaluation becomes costly at scale. I would carry forward the scheduling interface while requiring stronger behavioral qualification and closed-loop quality-adjusted evaluation before generalizing the headline performance claims.
