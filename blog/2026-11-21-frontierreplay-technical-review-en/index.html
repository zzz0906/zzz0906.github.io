    FrontierReplay: Exact Hybrid Prefix States Without Cutting the Forward Pass

    Review date: 2026-11-21
    Author: Zhongzhu Zhou
    Paper reviewed: FrontierReplay: Split-Free Exact Prefix Caching for Hybrid Language Models
    Paper authors: Zekun Wang, Yizhuo Wang
    arXiv: 2611.26020
    Version and date: v1, 2026-11-19

    1. What problem the paper actually solves

    My central reading is that FrontierReplay separates three decisions that are often conflated: where a reusable prefix ends, how to obtain the recurrent state at that position, and whether that state deserves scarce GPU memory. Its contribution is the combination. Saving more checkpoints is insufficient if obtaining each checkpoint adds a scheduler step; making checkpoints cheaply is insufficient if obsolete conversation states displace the next useful anchor.

    In an attention-only model, cached keys and values can be truncated at a page boundary. In a hybrid model, a recurrent layer folds history into one mutable tensor. The tensor after token 2,000 is not a container from which the state after token 1,984 can be sliced. To resume at 1,984, the system needs the state at exactly that position, including the small convolution buffers accompanying the recurrence. A long resident KV prefix can therefore be unusable because its matching recurrent state is absent.

    The paper’s answer is to run an ordinary prefill chunk, temporarily record the inputs that its recurrent layers actually consumed, and then replay only their state transitions from a saved anchor. This second computation omits attention, MLPs, and recurrent output construction. It materializes a middle-of-chunk state after the forward pass, without forcing a new host scheduling iteration. The result becomes a normal checkpoint for future requests.

    I read all 15 pages of v1, including the 12 figures, four tables, and references; this version has no separate appendix. All performance numbers below are the authors’ measurements. My equations, toy rounding example, and cost arithmetic explain the mechanism; they are not new model or serving experiments. A further disclosure matters for the comparison section: I am a coauthor of the related FlashState work cited by this paper under the name FlashStates. I distinguish the authors’ adapted export baseline from an evaluation of that entire separate system.

    The headline result is conditional: at the eight primary 9B/7B operating anchors, FrontierReplay improves goodput by 1.11–4.26 times over the paper’s vLLM configuration. At a different, memory-bound 34B LongBench point, it reaches only 0.76 times vLLM goodput despite a lower median TTFT. Both observations belong in the assessment [1, §6].

    2. Prerequisites: two kinds of history and two kinds of cost

    KV pages and recurrent state are different objects

    Let bbb be the longest prefix whose attention KV pages remain resident, and let C\mathcal CC contain the committed recurrent checkpoints with a fully reachable KV prefix. A request can resume at

    c⋆=max⁡{c∈C:c≤b},Δ=b−c⋆.(1)c^{\star}=\max\{c\in\mathcal C:c\le b\},\qquad \Delta=b-c^{\star}. \tag{1}c⋆=max{c∈C:c≤b},Δ=b−c⋆.(1)

    Here Δ\DeltaΔ counts resident-prefix tokens stranded by the missing state. The maximum includes the empty initial state when nothing deeper is available. This expression is my compact restatement of the lookup rule in §4.1, not a new paper theorem. A checkpoint beyond bbb cannot repair missing attention KV; conversely, KV through bbb cannot reconstruct an earlier recurrent state by itself. Reuse requires the intersection of both resources.

    Figure 1: From paper Fig. 2. Original diagram from Wang and Wang [1]. The orange span is recomputed through the full model because the recurrent state is available only at the earlier grid point. The drawing concerns granularity, not an extra approximation introduced by FrontierReplay.

    The paper uses 16-token attention pages. Its vLLM align grids are 528 tokens for Qwen3.5-9B and 1,568 for Falcon-H1-7B, selected to match state bytes to attention-page bytes. If a shared prefix ends at token 2,000, a 528-token grid resumes at 1,584 and strands 416 tokens. A 1,568-token grid resumes at 1,568 and strands 432. These are illustrative integer examples; actual shared-prefix lengths vary. Even fine 16-token checkpointing still leaves fewer than 16 trailing tokens when a logical boundary is not page aligned.

    Prefill tokens and scheduler iterations are separate budgets

    Prefill processes prompt tokens; decode generates the continuation. Continuous batching interleaves both. Chunked prefill limits how many prompt tokens occupy one iteration so that long prompts do not monopolize decode service. Ending a chunk early to capture a state can increase the number of iterations even when the total prefill token count stays fixed.

    The authors isolate that cost by holding checkpoint locations and computed tokens constant. Cutting raises prefill steps by 1.44–1.86 times on chat, tool, and tree traces, but only 1.05–1.09 on document questions where target cuts are sparse [1, §3.2]. It would be incorrect to attribute the resulting slowdown entirely to extra floating-point operations: the scheduler has to revisit short residual chunks, and other requests share the resulting execution timeline.

    Figure 2: From paper Fig. 3. Original execution comparison [1]. The replay remains real GPU work. Split-free means it does not add a checkpoint-induced prefill cut; ordinary chunked prefill still exists.

    Qwen interleaves Gated DeltaNet and attention layers; Falcon runs recurrent and attention heads in parallel hybrid blocks. Logging every recurrent layer’s real inputs is essential in either layout. Replaying only the first layer and regenerating all later inputs would reintroduce the expensive network computation the method is trying to avoid.

    3. Deriving state-only replay

    Mamba-2: the unrolled affine recurrence

    For one head, the paper writes the simplified Mamba-2 update as

    Sj=αjSj−1+Bj,Bj=vjkj⊤,oj=Sjqj.(2)S_j=\alpha_jS_{j-1}+B_j,\qquad B_j=v_jk_j^{\top},\qquad o_j=S_jq_j. \tag{2}Sj​=αj​Sj−1​+Bj​,Bj​=vj​kj⊤​,oj​=Sj​qj​.(2)

    SjS_jSj​ is dv×dkd_v\times d_kdv​×dk​, vjv_jvj​ has dvd_vdv​ entries, and kj,qjk_j,q_jkj​,qj​ have dkd_kdk​ entries. The decay αj\alpha_jαj​ lies between zero and one. Token indices in this section are relative to a saved anchor S0S_0S0​; the actual token position is the anchor plus jjj. Computing ojo_joj​ is necessary in the original forward, but is unnecessary when the only desired output is a later state.

    Substitution shows the structure before the compact formula hides it:

    S1=α1S0+B1,S2=α2α1S0+α2B1+B2,S3=α3α2α1S0+α3α2B1+α3B2+B3.(3)\begin{aligned} S_1&=\alpha_1S_0+B_1,\\ S_2&=\alpha_2\alpha_1S_0+\alpha_2B_1+B_2,\\ S_3&=\alpha_3\alpha_2\alpha_1S_0 +\alpha_3\alpha_2B_1+\alpha_3B_2+B_3. \end{aligned} \tag{3}S1​S2​S3​​=α1​S0​+B1​,=α2​α1​S0​+α2​B1​+B2​,=α3​α2​α1​S0​+α3​α2​B1​+α3​B2​+B3​.​(3)

    Define γi:h=∏ℓ=ihαℓ\gamma_{i:h}=\prod_{\ell=i}^{h}\alpha_\ellγi:h​=∏ℓ=ih​αℓ​, taking an empty product as one. Continuing the substitution gives

    Sh=γ1:hS0+∑j=1hγj+1:hvjkj⊤.(4)S_h=\gamma_{1:h}S_0+ \sum_{j=1}^{h}\gamma_{j+1:h}v_jk_j^{\top}. \tag{4}Sh​=γ1:h​S0​+j=1∑h​γj+1:h​vj​kj⊤​.(4)

    This is the paper’s Eq. (2), with the anchor index suppressed. The formula explains both what is saved and what can be skipped. Each layer needs its own initial state and the exact decay/key/value sequence. It does not need its queries, per-token outputs, attention computation, or MLPs to construct ShS_hSh​ after those inputs have been recorded. The convolution history is an additional state component; logging the recurrence alone is not a complete checkpoint specification.

    Gated DeltaNet: matrix products cannot be treated as scalar decay

    The paper gives the GDN transition as

    Sj=Sj−1Aj+Bj,Aj=αj(I−βjkjkj⊤),Bj=βjvjkj⊤.(5)S_j=S_{j-1}A_j+B_j,\quad A_j=\alpha_j(I-\beta_jk_jk_j^{\top}),\quad B_j=\beta_jv_jk_j^{\top}. \tag{5}Sj​=Sj−1​Aj​+Bj​,Aj​=αj​(I−βj​kj​kj⊤​),Bj​=βj​vj​kj⊤​.(5)

    The right multiplication first erases a direction associated with the key and then writes the new association. With ordered products, the same affine reasoning yields

    Sh=S0A1A2⋯Ah+∑j=1hBjAj+1⋯Ah.(6)S_h=S_0A_1A_2\cdots A_h+ \sum_{j=1}^{h}B_jA_{j+1}\cdots A_h. \tag{6}Sh​=S0​A1​A2​⋯Ah​+j=1∑h​Bj​Aj+1​⋯Ah​.(6)

    For example, the first contribution is B1A2A3B_1A_2A_3B1​A2​A3​ at step three, not A3A2B1A_3A_2B_1A3​A2​B1​. Shapes already rule out some reversed expressions; noncommutativity rules out the rest. The paper uses a chunkwise WY representation to handle products of rank-one updates efficiently. It does not claim that a GDN head can be replayed by replacing every matrix with the scalar γ\gammaγ of Eq. (4).

    The deeper reason cross-layer replay works is data dependence. In the original forward, layer two depends on layer one’s output. After all recurrent-layer input sequences have been logged, that dependence has already been resolved. Separate layer states can advance from their recorded inputs without recomputing the interleaved model. This is a sufficient-information argument, conditional on the log capturing all transition inputs and auxiliary buffers. It is not permission to reuse arbitrary old hidden states from a different model, template, or prefix.

    I independently checked Eqs. (4) and (6) with small synthetic matrices and checked that reversing GDN product order changes the result. This verifies the algebra used in this note, not the authors’ implementation or their performance measurements.

    4. Exactness includes the rounding schedule

    The algebra above is over real numbers. Actual kernels round states when they cross chunk or decode boundaries. Applying the same symbolic recurrence in a different grouping can therefore produce a different stored state. FrontierReplay records bitmasks for the boundaries at which the original execution rounded to storage precision, then segments replay and rounds at those same positions [1, §4.2].

    To make the dependency explicit, let FjF_jFj​ be an ideal state transition and RjR_jRj​ either the prescribed rounding map or the identity. The desired replay follows

    S^h=(Rh∘Fh)∘⋯∘(R1∘F1)(S^0).(7)\widehat S_h=(R_h\circ F_h)\circ\cdots\circ (R_1\circ F_1)(\widehat S_0). \tag{7}Sh​=(Rh​∘Fh​)∘⋯∘(R1​∘F1​)(S0​).(7)

    In general, this is different from applying RhR_hRh​ only once after an unrounded closed-form computation. Matching the mathematical final sum is insufficient. Nor does knowing that a state uses FP32 or BF16 completely describe its numerical history: the original scheduling boundaries also matter.

    Figure 3: Original explanatory calculation by Zhongzhu Zhou. Starting at 1, the scalar update is S←0.9S+0.06S\leftarrow0.9S+0.06S←0.9S+0.06. Rounding to the nearest 0.1 after each token gives 1.0; rounding only after two steps gives 0.9. This decimal toy is not a BF16 error measurement or a model experiment.

    The authors report bit-for-bit agreement between a replayed state and the corresponding uninterrupted forward state under their comparison setup. They separately report 92% token-identical greedy outputs across serving tests, despite matching task scores. The remaining output differences are attributed to near-tie floating-point changes caused by dynamic concurrent batch shapes, with zero non-tie argmax flips [1, §3.3, §6.3]. These statements are compatible because they test different objects under different execution conditions.

    I would keep three claims distinct. First, replay can preserve a fixed forward’s state when its inputs and rounding schedule are preserved. Second, changing batching can perturb floating-point logits even for exact caches. Third, a task score near 100% relative to baseline is not a proof that every generated string is identical. The paper’s 100.2–100.3% relative scores do not establish an accuracy improvement; its stated p≥0.34p\ge0.34p≥0.34 supports treating those scores as comparable in those tests.

    Falcon also has a practical restore floor: the planner does not place or restore states below 1,568 tokens, because short BF16 Mamba-2 states are sensitive before decay has reduced the initial history’s influence. This is an explicit numerical design boundary. It prevents me from describing the system as unrestricted exact reuse at every 16-token boundary. The boundary can be represented at page granularity only when the anchoring, numerical, and resource conditions are met.

    The alternative of approximate suffix replay intentionally drops distant history and rebuilds from a short tail. That can be sensible when a task tolerates error, but it is a different contract. Small decays do not by themselves guarantee harmless truncation: keys, gates, and long-context tasks can preserve or amplify precisely the information discarded by a suffix heuristic.

    5. The checkpoint production protocol

    Figure 4: From paper Fig. 5. Original architecture [1]. The input log is temporary staging memory, whereas KV pages and recurrent checkpoints are persistent reuse resources. Dashed control arrows should not be read as GPU-wide synchronization.

    The scheduler first finds the longest resident KV prefix, then the deepest reachable checkpoint on it. Restoring that checkpoint copies its state into a request’s mutable working slot. The saved checkpoint must remain separate: the next forward overwrites the working state, so replay cannot later use that slot as an untouched starting anchor. A lease keeps the saved starting state alive until its dependent replay finishes.

    The planner selects targets inside the coming chunk. Logging copies the recurrent-layer inputs from chunk start through the deepest target into private 16-token log pages. Siblings may share immutable prefix state but must not share mutable logs. Otherwise, one sibling could overwrite another’s projected inputs and produce a numerically plausible state for the wrong continuation. Request-private staging is a correctness choice as well as a contention policy.

    Algorithm 1. Produce and commit exact target checkpoints

    This numbered pseudocode restates §§4.1–4.2 and §4.6; it is explanatory rather than a reproduction of source code.

    1. Look up resident KV end b and deepest committed checkpoint c <= b.
2. Lease c; copy it into the request's working state.
3. Plan ordered target positions inside the next ordinary prefill chunk.
4. Require a live chunk-start anchor, output slots, and input-log pages.
5. If the window exceeds 1024 tokens, plan an exact boundary cut.
6. If preparation lacks an anchor or log capacity, fall back to a cut.
7. Run the intact forward chunk; log each recurrent layer's real inputs,
   auxiliary convolution information, and precision-boundary bitmasks.
8. On the same CUDA stream, replay from the leased starting anchor;
   store each target state and reproduce the recorded rounding points.
9. Record the step's completion event; keep targets invisible meanwhile.
10. After event completion, publish successful target checkpoints.
11. Release temporary logs and leases; discard incomplete failed work.

    Two ordering rules deserve emphasis. Enqueuing the original forward and replay on the same stream establishes a device happens-before relation: replay reads inputs only after their writes. Publishing the pointer to the host index is a separate event-lifecycle decision: future lookups must not receive a state whose GPU write is still pending. Avoiding a blocking host wait does not mean ignoring completion.

    Resource cleanup has the same distinction: a low-value checkpoint can remain leased by pending work. Its bytes cannot be reclaimed until dependencies finish, including after preemption or failed steps. Exact-cut fallback preserves correctness while losing the intended performance advantage.

    The maximum replay window is 1,024 tokens. Wider targets proactively become cuts; runtime preparation can also fall back if a live starting anchor or free log page is unavailable. In the primary setup, median and p90 windows are 96 and 768 tokens, and 99.5% of eligible within-window operations complete without fallback. That percentage is conditional on the paper’s window scope; it should not be converted into a universal guarantee that 99.5% of all requests avoid every kind of cut.

    Cross-layer device pointer tables reduce launch sequences compared with launching a separate replay pipeline for every layer. Warmup compiles and captures logging, copying, and replay kernels. These details explain how an extra GPU phase can remain cheap while preserving CUDA-graph-compatible addresses. They do not eliminate the allocation, copy, or staging footprint.

    6. Predict boundaries from structure, not future traces

    The planner uses four kinds of positions. At startup, it compares two rendered chat-template conversations to identify the stable suffix boundary between an existing turn and the next generation prompt. For each request, the corresponding position is a candidate next-turn anchor. When decoding finishes, the last complete 16-token boundary of prompt plus generated output is also saved; decode has naturally passed through that state, so creating it needs a copy rather than post-forward replay.

    A known branch junction is another target. If a radix node already has two children and is at least 256 tokens deep, a later request can establish a checkpoint there for future siblings. This is causal information from earlier traffic. The system cannot retroactively give the first two siblings a state that did not exist when they arrived. Natural chunk ends supply additional low-priority candidates because their recurrent states are already available.

    The measured opportunity is strong: 79–100% of reusable tokens in the eight primary model/workload pairs end at earlier turn boundaries, and at most 8% end at previously unseen branch points. Those numbers characterize the selected traces [1, §3.1]. They are not a theorem about all agent traffic. Arbitrary document edits, retrieval-order changes, nonstandard templates, or clients that regenerate serialized metadata can move reuse away from those structural positions.

    Template probing is attractive because it avoids learning an overlap distribution and requires no future trace oracle. Its failure boundary is template dependence. If tool formats, system headers, or template versions change, the inferred stable end may no longer identify the next shared prefix. The conservative response is to re-identify stable structure and preserve exact fallback behavior; the note does not assume a single startup probe proves every possible template branch stable.

    The branch rule has a complementary cold-start cost. A shared document may initially have no proven junction. Saving a natural deep checkpoint can still prevent the entire document from becoming stranded. FrontierReplay protects one existing natural checkpoint per long-prefix group: it must be within one 2,048-token prefill budget before the template-stable end and at least 4,096 tokens from the start. While its KV remains resident and no deeper reachable junction exists, it receives proven-tier priority.

    That protection is intentionally narrower than saving every document tail. A question-specific prompt-end state can lie beyond the document prefix shared by later questions. Keeping only that tail would have a high token position and still be useless for the next query. The long-prefix rule instead protects a checkpoint likely to lie before divergence. The exact constants are reported operating choices, not universal optimum values derived by the paper.

    I find this structure-based reasoning more persuasive than a claim that fine checkpoint spacing alone solves hybrid caching. A useful position is one that an actual future request can reach with both its KV and recurrent state intact. Placement, lifetime, and available prefix bytes jointly determine that reachability.

    7. Frontier retention and dead-slot reclaim

    Why ordinary recency can preserve the wrong history

    A conversation continually creates new anchors. The newest anchor may have zero past hits precisely because its next turn has not arrived. Older ancestors can have many historical hits while being dominated by a deeper state on the same branch. A pure frequency score can therefore evict the state needed next and keep the states already passed. FrontierReplay adds structural tiers to that decision.

    Figure 5: Original Mermaid summary of §4.4 [1]. The arrows indicate increasing retention priority, not mandatory transitions between states. Long-prefix protection can give an existing natural checkpoint proven-tier priority; an active lease independently prevents premature reuse of its storage.

    The tiers are dead (−1)(-1)(−1), superseded (0)(0)(0), speculative natural (1)(1)(1), untested turn anchors (2)(2)(2), proven (3)(3)(3), and running (4)(4)(4). A dead checkpoint has lost some KV page in its prefix. A superseded checkpoint has a deeper usable state along a path without an intervening branch under the conditions specified in the paper. Proven includes branch junctions and states restored by at least two distinct requests. Running protects the anchor of a request still executing.

    Requiring two distinct restoring requests matters. If a single restore proved an anchor valuable indefinitely, every predecessor in a multi-turn chain would be promoted. Protecting every historical turn defeats the frontier idea. Similarly, new natural checkpoints are admitted to a full pool only if they displace dead or superseded entries. A free-to-produce state still has a substantial opportunity cost once it occupies tens of MiB.

    The initial description uses LRU to break ties within a tier. The long-prefix refinement also estimates how many reusable tokens would be lost without each state and evicts lower-loss entries first within a tier, promoting repeatedly useful states whose estimated loss reaches a prefill budget. I read this as a policy refinement rather than a claim that one scalar LRU order captures the entire final policy. A useful formal intuition is the marginal loss

    ℓ(c)=max⁡{0, c−cfallback},(8)\ell(c)=\max\{0,\ c-c_{\mathrm{fallback}}\}, \tag{8}ℓ(c)=max{0, c−cfallback​},(8)

    for a relevant future hit whose next reachable state is cfallbackc_{\mathrm{fallback}}cfallback​. This is my explanatory quantity, not the complete estimator in the paper. A branch with many possible successors and a running turn with a single imminent successor can both deserve protection for different reasons.

    Lending dead capacity to KV

    Separate pools can become unbalanced. KV eviction makes recurrent checkpoints dead; retaining those bytes cannot create a reachable prefix. Every 16 requests, the controller counts states that died because their KV disappeared. If no checkpoint above tier zero was evicted in the previous four periods, it can transfer up to min⁡(16,2d)\min(16,2d)min(16,2d) slots, where ddd is the dead count, to the KV pool. It evicts only tier-zero-or-lower entries and keeps a floor covering working states of running requests [1, §4.5].

    The controller excludes deaths caused by its own reclamation from its input signal. Without that rule, shrinking a pool could manufacture more apparent pressure and trigger further shrinking. The quiet-period guard also tries to avoid lending bytes when checkpoint capacity is already binding. These are feedback-stability choices, not merely bookkeeping.

    CUDA virtual-memory page remapping preserves virtual addresses while changing backing allocation, which helps CUDA graph reuse. But it does not magically unify all allocations: live state slots, contiguous reclaim constraints, and fixed tensor-parallel subpools can still prevent a transfer. The 34B LongBench counterexample later shows that this distinction is consequential.

Provisioned address/backing capacity and bytes written in an average step measure different things. Neither average write size nor low GPU-time share justifies calling the memory overhead negligible.

    9. Evaluation: read the service definition before the speedup

    The primary platform is one A800 80 GB GPU, BF16 weights, a 2,048-token chunked-prefill budget, piecewise CUDA graphs, and a 32 GiB cache budget. Qwen3.5-9B has 24 GDN and eight attention layers with FP32 recurrent state; Falcon-H1-7B has 44 parallel hybrid blocks and BF16 recurrent state. The larger 27B/34B points use two-way tensor parallelism and fixed per-GPU pools [1, §6.1]. These settings should travel with the results.

    The workloads are ShareGPT multi-turn windows, SWE-agent tool sessions, LongBench document questions, and eight-branch GSM8K tree search. Sessions arrive as Poisson processes; dependent child calls are issued after the parent completes. Recorded responses are replayed identically across systems for timing. This controls response-length differences, but it also means the performance study is not an unrestricted live-agent study in which output changes alter the future tool trajectory.

    The joint SLO is TTFT at most 500 ms and mean TPOT at most 50 ms. A call contributes to goodput only if it satisfies both within the 180-second timeout. In compact form,

    G=∑i=1N1{Tfirst(i)≤500ms, T‾token(i)≤50ms, Tcall(i)≤180s}Twall.(13)G=\frac{\sum_{i=1}^{N}\mathbf1\{ T^{(i)}_{\mathrm{first}}\le500\mathrm{ms},\ \overline T^{(i)}_{\mathrm{token}}\le50\mathrm{ms},\ T^{(i)}_{\mathrm{call}}\le180\mathrm{s}\}} {T_{\mathrm{wall}}}. \tag{13}G=Twall​∑i=1N​1{Tfirst(i)​≤500ms, Ttoken(i)​≤50ms, Tcall(i)​≤180s}​.(13)

    I use an explicit timeout indicator to make the paper’s definition clear. Goodput is completed SLO-passing calls per wall second, not raw generated tokens per second. Table 3’s TPOT p99 describes a tail distribution; it is not the same quantity as the per-call mean TPOT used in the SLO. A tail above 50 ms therefore need not imply that every call fails.

On Falcon SWE-agent, 4.26 times goodput at offered load two calls/s is not a claim that sustainable load increases by 4.26 times: the reported 80% capacity gain is about 1.60 times.

    The capacity statistic is

    C0.8=sup⁡{λ:ASLO(λ)≥0.8},(14)C_{0.8}=\sup\{\lambda:A_{\mathrm{SLO}}(\lambda)\ge0.8\}, \tag{14}C0.8​=sup{λ:ASLO​(λ)≥0.8},(14)

    interpreted over the measured load sweep and its operational interpolation. It describes a service threshold, while anchor goodput describes one operating point. The authors use 80% because several workloads fail to reach 90% even at low load. That is informative about workload difficulty; it also means this paper does not establish a 99%-attainment production SLO.

    Replication depth varies. Anchors, ablations, and multi-run 27B/34B points use three paired runs with Student-ttt intervals. Full sweeps, many sub-32-GiB budgets, 4B points, and dagger-marked comparisons use one paired run. A three-run interval is useful but based on only two degrees of freedom; it should not be confused with a broad estimate of traffic and hardware variation. I would prioritize additional seeds around the collapse boundaries, where small timing changes can create large goodput ratios.

    10. Approximate reuse and mechanism attribution

    Accuracy comparisons are a separate experiment

    Figure 8: From paper Fig. 8. Original RULER variable-tracking sweep [1]. The vertical axis is accuracy relative to vLLM, not absolute task accuracy. Values above 100% are small relative-score changes and do not establish better model quality.

    The accuracy study uses 303 LongBench, needle, and RULER items plus an 800-question variable-tracking sweep. FrontierReplay’s relative scores remain near parity, whereas SuffixReplay* loses 13–17% relative accuracy on the 24K/32K variable-tracking cases with a 512-row tail. Reducing the tail to 128 worsens the reported loss to 15–18%. These results support a concrete long-range-information risk, not the claim that all approximate state methods fail by the same amount.

    The approximate comparator is an independent paper-description-based adaptation because its original source was not released. It rebuilds from zero over at most 512 sampled hidden rows under the paper’s configuration. That choice matters: a conclusion about this comparator cannot automatically be assigned to every possible learned approximation or every future version of SuffixReplay. The authors’ explicit star helps keep the identity honest.

    At high contested loads on Qwen, exact replay ties the approximate method on chat and tool sessions and wins on LongBench and ToT. Table 4 gives mean goodput ratios of 1.538 [1.48, 1.59] for LongBench at load six and 1.101 [1.04, 1.16] for ToT at load sixteen. The ShareGPT mean is 0.986 [0.90, 1.07], which is a tie rather than an exact-method victory. A checkpoint pays replay once and then copies at hits; approximate suffix reconstruction pays its reconstruction cost repeatedly. That amortization can offset the persistent checkpoint bytes.

    The ablations support a layered explanation

    Figure 9: From paper Fig. 9. Original cumulative ablations [1]. Each panel has its own workload and operating condition; its absolute calls/s should not be silently substituted for a Table 3 anchor.

    Removing cuts is the largest isolated mechanism in several settings, but not the sole source of the final gain. On Falcon SWE-agent, the cut-based stable-anchor configuration reaches 0.37 calls/s, split-free execution 0.67, and the final design 0.74, against 0.19 for vLLM in that ablation. On Qwen LongBench, frontier/junction protection moves 2.39 to 2.58 calls/s. Those examples explain why token reuse alone is an incomplete metric.

    The ablation sequence is cumulative, so the marginal effect of one component is conditional on those already enabled. It does not establish that each component contributes the same amount under every ordering. Nor do the 0.74-call/s ablation result and the 4.26-times Table 3 anchor form a contradiction: they come from separately reported settings/runs. I preserve their labels instead of mixing their numerators and denominators.

    At 16 GiB, Falcon tool sessions expose a different bottleneck: checkpoint slots, not log exhaustion, force about 7.2% fallback to exact cuts, and all systems saturate below roughly 0.21 calls/s at the stated 16–24 GiB points. Adding log pages alone would not repair that resource shortage. On Qwen16-GiB tool sessions, the paper instead reports 98.7% split-free completion and 1.37 versus 0.76 calls/s, showing that the binding resource depends on model state size and workload.

    The paper reports replay/restore and host scheduling overhead each at at most 1.2% in the primary anchors. The low measured time share is credible in a regime with many avoided expensive prefills. It remains a measured fraction under those workloads, not a bound for sparse-reuse or tiny-model traffic.

    11. Limitations and explicit counterexamples

    Figure 10: From paper Fig. 12. Original scale comparison [1]. The highlighted 34B LongBench bar is below parity in goodput even though its median TTFT speedup exceeds one. The 4B ToT goodput bar is also approximately parity.

    Lower latency does not imply higher goodput. On 34B LongBench at load 0.5, median TTFT falls from 225 to 135 ms, a 1.67-times speedup. Goodput is only 0.76 times vLLM. Hit rate falls from 0.90 to 0.83. Fixed tensor-parallel subpools offer 22 GiB KV plus 82 state slots per GPU rather than a unified 32 GiB cache, and live tail slots block 22 reclaim attempts [1, §6.5]. A faster hit path cannot compensate if enough other requests lose valuable KV capacity.

    Small models can be below the useful-amortization threshold. On 4B ToT at load twelve, the method removes 18 TPOT misses but adds seven milliseconds to median TTFT, from 55 to 62 ms, and yields about 0.99 times goodput. The paper’s passing-call counts differ by only one, 445 versus 444; a single-run near-parity point is not strong evidence of a systematic regression, but it prevents a blanket claim of improvement everywhere.

    In-kernel export can win. On fine-tile GDN, the authors’ adapted multi-target export is 1.5–2.5% better on the reported chat/tool follow-ups. On coarse-tile Falcon Mamba-2, off-tile scans make export more expensive and replay wins. These dagger-marked follow-ups are single paired runs. The evidence supports a tile- and workload-dependent crossover, not a universal replay-over-export ordering.

    No checkpoint resource is free. Temporary logs occupy real slabs; recurrent checkpoints are large; saved working anchors consume slots; a lease can delay reclamation. VMM preserves addresses but does not remove live-allocation constraints. The method’s strongest design tradeoff is exchanging bounded extra state/log memory for fewer full-model recomputations and scheduling cuts.

    Structure can change. The measured boundary concentration depends on templated sessions and known branches. Novel branch points, short Falcon prefixes, template changes, and wide replay windows all reduce the fraction of reusable work captured without cuts. Exact fallback preserves semantics while potentially eroding the performance result.

    The evaluation is narrower than a deployment guarantee. A800 hardware, a particular runtime, fixed state precisions, Poisson arrivals, replayed responses, and four traces leave bursty multi-tenant traffic, other GPU generations, long think times, changing templates, and live tool feedback incompletely tested. The paper does not provide evidence that every such setting has the same boundary histogram or memory balance.

    Finally, the paper’s concurrency-sensitive numerical explanation means exactness must be stated at the correct level. The strongest claim is preservation of the intended recurrent-state computation under captured inputs and rounding boundaries, supported by their state checks and task tests. It is not an unconditional byte-identical transcript guarantee across all scheduler histories.

    12. Critical analysis: what I would test or change next

    Replace fixed pool intuition with measured marginal value

    The most consequential weakness is not the replay kernel; it is deciding how much memory to reserve for reusable states versus attention KV. The 34B document counterexample supplies a direct falsification of the idea that low replay cost ensures service benefit. A next design should compare the marginal avoided prefill of one additional checkpoint with the marginal KV reuse lost by reserving its bytes, while accounting for active leases and fragmentation.

    I would evaluate an adaptive partition with a unified-byte-budget comparator, not merely increase the checkpoint pool until a favorable trace improves. The measurement should include failed reallocations, dead-but-not-reclaimable bytes, lease durations, reuse distance, and the fraction of KV-resident prefixes stranded by absent states. A controller should be judged on total goodput and tail latency after phase changes, because aggressive reclaim can improve a steady average and still harm the next session burst.

    Make placement robust to imperfect structural predictions

    The four placement rules are interpretable, but the template probe and branch warmup can be wrong or late. I would vary template branches and client serialization while holding semantic conversations constant. Then I would compare predicted boundaries with actual future longest common prefixes, separating unseen-junction misses from eviction misses and numerical-floor exclusions. This identifies whether to improve prediction, enlarge memory, or simply accept a correctness-preserving cut.

    A useful extension is a confidence-aware target budget: retain high-confidence turn anchors, allocate a small exploration budget to uncertain junctions, and reduce that budget when replay is rarely reused. This is my proposed direction, not a feature demonstrated in v1. It must use only past observations; training a planner with future trace positions and reporting that as online performance would invalidate the causal argument.

    Clarify exactness as an executable numerical contract

    The rounding bitmask is an excellent systems detail, but it makes portability an obligation. Kernel changes can alter rounding locations or auxiliary buffer semantics even when model shapes stay constant. A numerical contract should describe state dtype, transition inputs, convolution buffers, rounding masks, and publication lifecycle. A new backend should re-establish fixed-forward state agreement before comparing throughput.

    The next experiment should isolate state-level replay equality, logit deviations at a fixed batch shape, and output variation under dynamic batching. Reporting the top-two-logit margin alongside token disagreements would distinguish genuine state error from a near-tie argmax effect. This suggestion concerns paper-level experimental design and numerical validation; it does not assume any undocumented property of the authors’ source code.

    Compare mechanisms on equal budgets and report decision regions

    The baseline ports and common runtime help isolate policies, yet fixed partitions differ from vLLM’s unified budget. I would sweep the split for each method, include a total-budget frontier, and show where export, cuts, and replay each dominate. A selector combining native export at tile-aligned targets with replay at off-tile targets is plausible, but its integration and capture complexity could outweigh a small isolated saving.

    The FlashState relationship also calls for careful attribution. The paper compares a multi-target export adaptation inspired by that work, with its own kernel changes and graph signatures. Its result should be attached to that exact comparator and target layout. It cannot establish that the original complete FlashState system would have precisely the same end-to-end performance. My coauthorship gives me a reason to be especially strict about this boundary in both directions.

    A useful decision map would span model size, tile width, reuse rate, active sessions, and KV pressure. The two negative points already identify boundaries that a maximum speedup hides.

    13. Reproducibility and an operational reading checklist

    The paper is sufficient to explain the mechanism, but reproducing its service numbers would require workload tokenization, response traces, admission timing, pool layouts, exact/approximate baseline definitions, numerical precision, and run-level measurements. No model or serving experiments were run for this note. Official runtime links in the references are context rather than proof of a released FrontierReplay artifact.

    Algorithm 2. Decide whether a resident state remains useful

    The following sequence makes the policy and lifetime conditions explicit. It combines the paper’s retention rules into a reading aid; actual tie-breaking also uses estimated lost reuse and recency.

    1. For each candidate, test whether every prefix KV page is reachable.
2. If any required KV is missing, classify the checkpoint as dead.
3. Otherwise detect a dominating deeper state without a useful branch.
4. Classify remaining states as natural, untested turn, proven, or running.
5. Apply the long-prefix guard to one eligible deep natural state/group.
6. Exclude leased storage from physical eviction until dependent work ends.
7. Admit a new natural state in a full pool only over tier <= 0.
8. Evict the lowest eligible tier, using loss estimates and recency within it.
9. Every 16 requests, inspect externally caused dead states and pool pressure.
10. Lend only eligible dead/superseded capacity, respecting the running floor.
11. Keep controller-caused evictions out of its next dead-state signal.

    Before spending GPU time on a full comparison, I would request a reproducible description of these five evidence layers. The first is trace integrity: exact prompts, chat templates, recorded outputs, and causal child-call scheduling. The second is resource accounting: every KV, state, log, workspace, and working-slot byte, including the per-GPU tensor-parallel allocation. The third is semantics: complete recurrence and convolution state, precision history, and event-based visibility. The fourth is service accounting: both SLO dimensions, timeout treatment, measured load points, and wall-time denominator. The fifth is uncertainty: paired run results, separate seeds, and which figures use a single run.

    One arithmetic check illustrates why evidence layers should not be merged. A 1,100-to-125 ms TTFT change is an 8.8-times speedup and an 88.6% reduction. A 0.69-to-1.11 calls/s capacity change is a 60.9% increase. A 4.26-times anchor goodput ratio describes neither of those percentages. The paper can report all three consistently because they answer different questions.

    The most useful first operational test would replay a short trace with known branch points, one lost KV page, an unavailable start anchor, and a deliberately exhausted log pool. Every fallback should retain the exact-cut contract. A later performance sweep can then vary reuse frequency and memory pressure to find the point where making fewer checkpoints improves service. This is a proposed evaluation plan; no such deployment test was performed for this reading note.

    14. Conclusion

    FrontierReplay’s strongest idea is to treat a recurrent checkpoint as a materialized result of a short, logged state computation rather than as something obtainable only by ending the whole network forward. Logging inputs from the real forward resolves cross-layer dependencies; matching rounding boundaries preserves the numerical path; event-gated publication keeps asynchronous execution safe; frontier retention makes the resulting states relevant to the next request.

    My takeaway is conditional adoption. This design is particularly compelling when repeated structural prefixes otherwise force expensive full-model recomputation or extra scheduler iterations, and when state/log memory does not displace more valuable KV. It is less compelling when reuse is sparse, a small model already has decode slack, native export is cheap at the relevant tile boundaries, or fixed pools become the dominant capacity bottleneck.

    The next advance should adapt checkpoint placement, production, and memory allocation together. The paper’s production measurements and capacity counterexample provide a useful starting point.
