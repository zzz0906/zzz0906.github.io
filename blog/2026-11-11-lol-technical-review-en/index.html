    Library of Layers: Routing Whole Transformer Blocks at Runtime

    Review date: 2026-11-11 (UTC)
    Author: Zhongzhu Zhou
    Paper reviewed: Library of Layers (LoL): Adaptively Ordering Transformer Layers at Runtime
    Paper authors: Abdellah Rahmani, Sean McLeish, Ang Li, Sanae Lotfi, Pascal Frossard, Micah Goldblum
    arXiv: 2611.03526v1, 2026-11-02

    What changes when layers become selectable

    A decoder usually has two schedules. Its token schedule comes from autoregression, which produces tokens left to right. Its layer schedule is determined when the network is designed. Library of Layers (LoL) keeps the first schedule and learns part of the second. At each of a fixed number of core depths, a window of tokens uses a single transformer block selected from a shared library. The next depth can pick a different block, or it can reuse the same one. The same stored block can therefore receive very different hidden states across inputs and depths.

    I read the paper as an architecture study and an intervention study. The architecture study asks how to let the input choose the order of whole blocks while maintaining causal attention and competitive pretraining loss. The intervention study asks whether replacing the resulting path can control visible solution behavior. The measurements address these questions at different scales and on different training distributions. Results from a model trained to generate five kinds of maze trace should be interpreted separately from results on natural language or from claims about serving.

    Figure 1. Original schematic from Sections 3.1–3.2. Both illustrated token paths use three blocks, with different order and reuse. Attention and feedforward weights travel together with each expert.

    The critical constraint appears as soon as a routed component contains attention. An FFN can process a token on its own, so different tokens can use different FFN experts and still share a common attention layer. A complete block has its own query, key and value projections. If adjacent tokens choose independent blocks, the score between them may compare representations from different learned projections. That product is mathematically defined and could be trained under additional constraints. It changes the attention problem, and the paper reports poor stability and performance for the independent routing setup it tried. LoL groups tokens into windows and limits attention within each group. Window boundaries move across depth, allowing direct token interactions to cross an earlier partition.

    Dense, recurrent and sparse models offer three comparisons. A dense stack normally uses a different stored block at each depth. A looped stack reuses a fixed sequence of blocks. An ordinary FFN MoE adds a pool at each depth and chooses a subset for each token, while attention remains tied to the depth. LoL shares a pool of full blocks across depths. Its library size can create forced reuse or room for sparsity, while the router determines which blocks are actually used. Comparing these families requires distinguishing active compute, stored parameters and scheduling.

    A useful deployment property follows. At a fixed depth, each window has a stable identity and gate as the context grows. Earlier windows are already complete when the new window opens. The first token and the depth vector are stable for window zero. The cost of preserving that property depends on how the serving runtime maintains per-depth window boundaries and summaries. If it restarts window ordinals independently for each decode chunk, it changes the modeled function. With packed documents, resetting and isolating routing summaries at document boundaries is necessary to obtain per-document prefix independence. Appendix A explicitly documents blocked attention; the routing boundary should be tested separately when evaluating a packed execution.

    uℓ,s=γℓ,s⊙Norm⁡s(h)+βℓ,s.(7)u_{\ell,s}=\gamma_{\ell,s}\odot \operatorname{Norm}_{s}(h)+\beta_{\ell,s}. \tag{7}uℓ,s​=γℓ,s​⊙Norms​(h)+βℓ,s​.(7)

    Algorithm 1. Forward pass with shifted window routing

    This is a reader-oriented form of paper Algorithm 1 and Appendix A for a standard document. Accumulate the sum of preceding window means; computing the same prefix sum from scratch for every window would introduce unnecessary repeated work. The independent windows can be batched after routes are known.

    01  Apply the causal prelude to the token sequence; store H.
02  For each core depth l from 1 through D:
03      Partition indices using offset ((l-1) * S) mod W.
04      Compute each window mean from the unchanged H.
05      For each window k, form r using the earlier means.
06          For k=0, use (H[0] + depth_vector[l]) / 2.
07          Compute router probabilities (noisy in training).
08          Choose the argmax of probability plus selection bias.
09          Apply that expert with depth-conditioned normalization.
10          Within the block, attend only to causal keys in k.
11          Write next_H[k] = H[k] + probability * (block[k] - H[k]).
12      Replace H with next_H after all windows at this depth.
13  Apply the causal coda and vocabulary readout.

    Line 4 must read the input states of the current core depth, including when windows are processed in parallel. If later windows instead summarize earlier windows after their blocks are applied, the computation introduces an additional same-depth dependency. It can remain left-to-right causal, but changes the architecture and can serialize prefill. With the paper’s schedule, summarization is parallel, prefix means can be formed by a scan, and per-expert execution can group ready windows. Inference may drop the training noise without changing the causal proof. Forcing a path supplies both an expert ID and a gate at line 8 and line 11, while the attention mask and depth index stay as before.

    Capacity, compute and the growing schedule

    Stored blocks, uses and observed sparsity

    Growing the core during training

    The core starts shallow and adds routed depths during training. The paper reports a schedule described as one minus square root over the growing phase for the 1B math runs, occupying 75% of training. Appendix Figure 7 compares fixed depth 16 to growth from 1 to 16, and additionally plots a final-eight backpropagation variant with full backpropagation for first windows. On a step axis a shallower model may be worse while it is still growing. On a FLOP axis it can process more data early. The paper observes a modest terminal loss difference in the growth ablation, so comparisons should specify both the training axis and the attained depth.

    What it means to force a strategy

    The intervention begins with a controlled training signal. In the synthetic tasks, each problem is paired with traces from five specified strategies. During training, the strategy description is visible to the router and masked from the rest of the network. The loss covers the trace and answer. Sudoku puzzles retain 30–36 digits and are selected to be solvable by all five methods. Their step formats distinguish naked singles, hidden singles, crosshatching, propagation and DFS backtracking. Mazes use an 8×88\times88×8 loop-free grid with a path of at least 12 cells. The generator also selects cases where BFS explores at least three off-path cells and DFS backtracks, so the requested exploration order has a chance to be observable. Appendix C gives about 20M deduplicated sudoku sequences and 36M maze sequences over 7.2M mazes, with about 10B training tokens per task.

    Maze traces all use cell identifiers. BFS and DFS can produce the same final path through a tree, yet BFS discovers a frontier in breadth order and DFS can revisit a parent while backtracking. A* uses a Manhattan heuristic. Bidirectional BFS alternates frontiers, and dead-end filling removes leaves. Figure 19 makes the target-vs-trace distinction concrete: several strategies end with the same list of answer cells and differ strongly in the trace before it. This controls a surface-format shortcut present in sudoku. It still leaves a highly structured generator and a unique correct final path. The task asks whether the model can produce strategy-specific traces under these controls.

    Algorithm 2. Extract and apply a forced path

    01  For each strategy, run labeled validation traces teacher-forced.
02  Accumulate pre-bias probabilities by depth and window ordinal.
03  For each observed cell, divide by its observation count.
04  Store the winning expert ID and its mean probability.
05  On a fresh problem, replace the strategy field with neutral filler.
06  At each routed depth/window, supply the stored ID and gate.
07  Generate the trace and answer autoregressively.
08  Score requested strategy, legal trace and final answer separately.

    Line 2 uses observations from complete validation trajectories. At test time the stored template can be applied without seeing any future generated token. This distinction prevents a misreading of teacher forcing as test-time leakage. It also makes template support important. The appendix shows unobserved positions and says maze dead-end filling reuses the W2 expert sequence if W3 is reached. That is evidence of one fallback policy, not support for arbitrary trace lengths. A clean extension would track count, uncertainty and fallback behavior per cell, and report accuracy by whether the rollout stayed within supported cells.

    Reading strategy adherence and correctness separately

    The main text reports essentially perfect strategy adherence under forced routes, with the largest sudoku miss in the backtracking condition and the largest maze miss in bidirectional search. The appendix bars make it possible to read finer outcomes. In paper Figure 14, the S2 hidden-singles route shows 100% requested strategy, 96.5% trace rule-faithful and 98.5% answer correct. S5 shows 99.5%, 97.5% and 99.0%, respectively. The paper’s description of a correct trajectory requires legal steps, requested strategy and a correct solution. These marginal bars do not reveal the exact intersection. For S2, the reported rule-faithful and answer-correct rates alone constrain their intersection to 95.0–96.5% by the union bound. The main heatmap should therefore be read with its generated-strategy axis in view.

    Figure 6. Redrawn from paper Figure 14. The vertical axis is truncated to show small differences. The three columns measure different outcomes under the appendix caption’s forced-routing condition.

    There is a protocol labeling ambiguity worth preserving. Sections 4.1.3–4.1.4 refer to appendix Figures 14 and 18 when discussing evaluation with the strategy description in context, while both appendix figure captions say forced routing. The main Figure 3 and the protocol description directly support the forced-routing result. The appendix bars are identified by their own captions here, and I do not use them to estimate a forced-versus-prompted performance gap.

    Agreement with the template at each depth is a different quantity again. Appendix Figures 12 and 16 compare the chosen expert with the forced template. In sudoku’s first window the mode IDs match across strategies in Figure 13, while agreement can fall to zero at some depths in Figure 12. The strategy-specific paths diverge in later windows. A successful forced trajectory is compatible with low agreement in some cells. Several routes may be functionally similar, and changing the gate at the same time can compensate. I would compare route-only, gate-only and joint interventions before attributing control to the order of expert IDs.

    Reading routing features in natural language

    The multilingual run trains a 360M-scale model on a balanced mixture of ten FineWeb-2 languages for 10B tokens. For each sampled window, the authors concatenate the one-hot expert choices across depths and apply PCA. If vvv and v′v'v′ are such vectors with one hot coordinate per depth, each different ID contributes two to the squared distance, and matching IDs contribute zero:

A useful comparison would hold content constant through parallel text and transliterations, preserve document-level splits, and add probes based on the token sequence or prelude states. Those controls would clarify whether the route contributes information beyond surface features.

    For safety, the 360M model trains on a balanced mixture for 10B tokens without the harmfulness labels as targets. The classes come from score 0 versus scores 4 and 5 assigned to FineWeb sequences by an external classifier. The readout uses 40M development and 10M test tokens from a separate 50M-token set. Ridge on the full probability features has reported held-out AUROC 0.92 from a window and 0.95 after sequence-level pooling. A window inherits a document label even if it contains none of the responsible evidence. Pooling can reduce that label-feature mismatch and average out noise, while making an early-warning use case harder because some later windows have yet to arrive.

It does not settle whether the model would answer a harmful request, how well an alert threshold is calibrated, or whether the signal survives a change in language, domain or labeling convention.     Efficiency results and how to compare them

    Math at 1B parameters

    The math experiment uses 16 total applications with four prelude, eight core and four coda layers. LoL stores eight core experts. All runs use a mixture of Nemotron and OpenMath data, about 90 exaFLOPs, and the most compute-efficient model sees about 20B tokens. The paper matches parameter scale and compute and compares full, sliding and strided dense baselines. Appendix C.5 uses five shots except three on GSM8K to fit the 1,024-token context. Comparing loss across math and FineWeb would change the data distribution and the predictability of tokens.

    ARC-Easy illustrates why the baseline matters. LoL gains 9.5 percentage points over vanilla full attention but only 0.8 points over vanilla sliding attention and 1.8 points over vanilla strided attention. On GSM8K it trails vanilla full attention by 1.8 points and leads sliding attention by 0.4 points. These comparisons support competitiveness under the matched setup. They provide weaker evidence for a causal effect of dynamic layer order, since growth, attention pattern and routing differ between configurations. The standard errors in the table characterize benchmark estimates. They cannot substitute for repeated training runs with paired evaluation or show that two architectures are equivalent.

    On one math model, paper Figure 4 shows that some experts are concentrated across neighboring depths and some span wider ranges. This provides descriptive evidence of specialization, and helps explain why swapping experts arbitrarily is a demanding intervention. It does not establish how the expert distribution would change with context length or instruction tuning. In Appendix Figure 20 the extended dense and untied-router comparisons finish at broadly similar training loss. A closer test of order would compare adaptive LoL to the same library running a learned, input-independent route under identical masks, FiLM, token exposure and growth schedule.

    FineWeb and forced reuse

    The Huginn comparison trains 360M-effective-scale models on 10B FineWeb tokens. At core depth 16, libraries of 2, 4 and 8 are matched to recurrent blocks of two layers looped eight times, four looped four times, and eight looped twice. The authors tune at least six learning rates, consider multiple schedules and tune Muon and AdamW separately for the comparisons. Figure 5 uses three seeds, reports their min/max as bars in the evaluation plot, and averages the training curves. LoL is competitive at these matched scales and has larger spread in final evaluation loss. The authors suggest router initialization changes which paths are explored, a hypothesis consistent with the diverse depth-expert matrices in Appendix Figure 21. Three seeds constrain that conclusion. They provide neither the distribution of final loss nor evidence that initial routes explain all the variation.

    Stored, effective and non-embedding parameter counts answer different questions. At fixed DDD and width, reducing LLL saves weight storage, while the same number of applications still consumes activations and compute. When a looped baseline shares blocks, reporting the “360M” effective scale alone can make two storage budgets look identical even when they differ. The matched-size points are more informative than a single headline comparison. The depth-expert matrix measures marginal use across windows. It cannot determine how many distinct experts a token actually sees. Equation (9) is a reference for a new path-level measurement, not a reinterpretation of Figure 21.

    FineWeb and sparse MoE

    The sparse comparison uses 24 library experts at 16 core depths against a conventional three-expert, top-two MoE. This matches a nominal 3:2 ratio. The authors increase MoE expert intermediate width to align active parameters, give LoL MoE prelude and coda blocks, and use strided attention at the same depths in the MoE baseline. Runs use approximately 17 exaFLOPs and the most efficient one sees around 10B tokens. Figure 6 reports a small terminal training cross-entropy advantage for MoE, about 2.75 versus 2.80 for LoL, despite LoL’s early advantage under growth. The 0.05 cross-entropy gap corresponds to an illustrative ratio of exp⁡(0.05)≈1.051\exp(0.05)\approx1.051exp(0.05)≈1.051 in perplexity on the same tokenization and loss convention. It does not compare wall-clock, perplexity on a new dataset or performance on the 1B math tasks.

    The nominal ratio has different meanings. In the MoE case two of three FFN experts are active per token at each layer. In LoL’s core one complete block runs per token per depth, and the ratio compares depth with the number of available blocks. Distinct experts per path can be fewer than 16. Even if two architectures have the same ratio of active parameter applications to storage, they can differ in cache reuse, communication and batch utilization. A marginal heatmap from one seed can hide concentrated use for a subset of requests. Appendix Figure 22 usefully shows different specialization profiles across seeds. A systems comparison needs both use per device and expert occupancy for each real scheduling step.

    Limitations and reproducibility of the evidence

    LoL’s natural-language pretraining uses 1,024-token contexts and relatively small models. The full outer stacks, moderate context and training metrics matter to interpreting generalization. Strided core attention cannot move every individual token representation arbitrarily far in one step. Global access through the coda, prelude and routing summaries has different capacity and cost. Larger models and more heterogeneous batches may trade weight storage for fragmented execution. The paper does not provide a decode or serving benchmark that measures this trade.

    The released paper gives the architecture, mask and router, tokenizers, broad data construction, optimization setup and the ablation conditions. Appendix A specifies RoPE, RMSNorm, SwiGLU, bias-free attention, Muon alongside AdamW, document-blocked attention, and natural-language windows of 128 with stride 64. It uses GPT-NeoX tokenization for predominantly English FineWeb and OLMo3 for multilingual work. Synthetic first windows span the prompt and strategy field, and subsequent windows use 128/64 for sudoku and 64/32 for mazes. Those settings and the precise meaning of an input-dependent window are important when reproducing comparisons. I checked the equations and extracted figure and table values, and evaluated small arithmetic and dependency examples. The performance numbers in this review are the authors’ results.

    For a matched experiment, log tokens seen, the growth trace, training FLOPs and the parameter counts before benchmarking. Save the exact split unit for documents, puzzles and maze seeds. Probe comparisons are sensitive to whether multiple windows from one document cross the split. Template extraction is sensitive to whether validation and test puzzles have shared grids and to missing or sparsely sampled cells. Capturing these quantities makes a disagreement diagnosable. Loss alone would not say whether a change came from routing, mask support, token count or a different intervention.

    Critical analysis

    Is the path a control variable or an algorithm?

    The maze intervention demonstrates a meaningful control variable. The same output format and substantially different exploration orders make it harder to explain the result by syntax alone. But the strategy field is an explicit training-time channel into the router, and the learned representation is free to encode that condition in expert IDs, residual scales or the combination. The expert applied at one depth can depend on a depth-specific modulation, and later windows can reflect the already generated trace. It is possible for a stable early strategy cue to influence many later decisions without each named expert corresponding to a reusable search operation.

    I would use a factorial intervention across gate and ID and a control that preserves counts while changing order. On each held-out grid, keep either the original gate, the forced gate, or a matched constant while changing the ID sequence. Compare the reported template to a permutation of its expert multiset that preserves per-expert counts. Keep output prefix, window partition and evaluation limits fixed. In a second experiment, replace one depth range at a time and include matched random perturbations of the same size. Report strategy, legal steps, final answer and their joint score. A coherent shift in strategy under count-preserving reordering, with legal trace and accuracy intact, would better support an ordering effect. A gate-only effect would instead point toward conditioning through amplitude. Unseen cyclic mazes, novel sizes and new label-to-strategy mappings would test generalization beyond the fitted generator.

    A serving budget should measure reuse of weights and reuse of state

    With cached autoregressive decoding, a reasonable reference implementation would keep a route and gate per live window and depth, plus the earlier window-mean sum and the current window’s running hidden-state sum. The running sum must be taken from the block input, as in Algorithm 1. For attention, tokens in the active window can append key-value pairs under the same expert. Once a core window closes, later windows at that depth access it through summaries, while prelude and coda maintain their full-context caches. Treating a reused expert as one cache across depths would be invalid in general because its inputs and FiLM differ. This is a consequence of the described architecture. The paper does not present this cache as a measured result.

    Even a latency budget with equal active FLOPs can reverse with smaller or more scattered expert groups. As an illustrative cold-weight accounting, let BBB be the number of active windows at a decode step and UbU_bUb​ their distinct selected experts at one routed depth. Ignoring reuse across kernel calls and assuming one load per used expert, a cold-read weight budget at that step is approximately UbU_bUb​ times bytes per expert. When all windows choose the same block, Ub=1U_b=1Ub​=1. When eight windows choose eight experts, Ub=8U_b=8Ub​=8. Under ideal uniform independent routing with L=24L=24L=24 and B=8B=8B=8, equation (9) with BBB draws gives about 6.93. Real kernels can reuse weights from cache or combine work across requests, so the value is an accounting illustration. It explains why evaluating resident weights, HBM traffic, expert dispatch, occupancy and p95 per-token latency separately is more informative than reporting active FLOPs. Burst tests should vary whether requests hit window boundaries together and whether a prefill is concurrent with decode.

    Is dynamic order worth its optimization burden?

    The paper’s strongest efficiency evidence is that this architecture can learn under very different storage regimes. A decisive comparison for adopting it would train a fixed shared-library route and an adaptive route with the same growth schedule, router overhead budget, mask and modulation. A fixed route could be optimized offline or based on the most common path. A second baseline could choose once at a boundary and reuse its path for the entire next segment. This would trade responsiveness for fewer routing decisions and larger expert batches. Sweep LLL, DDD, WWW and SSS under matched measured time as well as reported FLOPs, and plot quality against both parameter bytes and p95 decode time. Include route concentration and marginal expert load so that a small gain can be attributed to input adaptivity rather than to added parameter capacity or a more favorable training schedule.

    There is a second opportunity in the pooling rule. Summarizing all completed windows gives older windows influence indefinitely but dilutes a recent event as 1/k1/k1/k. Adding a new mean μk\mu_kμk​ changes the cumulative router input by (μk−rk)/(k+1)(\mu_k-r_k)/(k+1)(μk​−rk​)/(k+1). At long context, a decisive token in a full new window first receives a 1/W1/W1/W mean coefficient and then a 1/(k+1)1/(k+1)1/(k+1) prefix coefficient. A learned decay or separate summary for the most recently completed window preserves causality and may improve responsiveness. It also risks overreacting to noise. A boundary-sensitive benchmark can insert a decisive cue at different positions and measure when and how strongly the route changes while controlling the token count and answer. That test would connect the current evidence about language and strategy to the actual time at which the architecture can use new information.

    Conclusion

    Library of Layers makes the order and reuse of whole transformer blocks depend on the input while maintaining a fixed number of core applications. Its most instructive mechanism is the combination of same-expert causal attention within a window, prefix-only selection and shifting boundaries across depth. The results support a feasible architecture and a strategy-control mechanism on deliberately constructed tasks. The next evidence I would look for is a controlled comparison that isolates dynamic order, plus a decoding benchmark that charges the actual cost of moving weights and maintaining per-depth state.
