    笔记日期： 2026-11-10（UTC）
    笔记作者： Zhongzhu Zhou
    阅读论文： On the Origin and Evolution of Training-Inference Mismatch in LLM Reinforcement Learning
    论文作者： Yu Li、Yufa Zhou、Tian Lan

    版本与日期： v1，2026-10-29

    1. 我带着什么问题读这篇论文

    假设训练端说：“这个 token 的概率是 0.12。”生成它的采样端却记了 0.08。直接拿两者相除，确实得到了重要性比率，却不知道该修哪个环节。可能两边用着同一版权重，只是引擎、精度和算子不同；也可能采样服务的权重落后几个训练步。前一种偏差在固定输入和固定采样版本下不会随着当前训练端移动，后一种则是训练自己造成的：本轮的更新改变下轮的比率，失真的梯度又可能放大下一次移动。

    论文的切入点是让训练引擎用采样时的权重再做一次前向。训练端当前分布、训练端旧权重分布、采样端实际分布这三份条件概率都对齐到同一个前缀和动作。于是，比较旧权重两端时只换引擎，比较训练引擎两份结果时只换权重。中间那份分布既是诊断工具，也是 DLC 的分母。

    我最关心的有三件事。第一，为什么「减去 score 的均值」能让量化场景稳定，却救不了冻结的采样器？第二，截断、裁剪与重新同步分别修掉哪部分偏差？第三，如果模型在旧前缀上的 KL 看起来没有异常，它自己生成的回答能不能已经崩掉？后文会发现，这三个问题分别对应均值、分布和采样覆盖范围，不能只盯同一个比率。

    先说结论的尺度：在论文的冻结采样实验中，DLC 确实有很强的稳定性证据，尤其是 1.7B；它在该配置下每步更慢。论文给出的半数 ESS 阈值是一条可测试的规则，不是适用于任意任务和引擎的稳定性定理。我会把三个判断分开：估计器是否纠正目标偏差、策略是否持续学习、训练系统是否更省时间。

    2. 前置知识：一批回答究竟来自什么分布

    2.1 把生成过程拆成前缀和动作

    用 xxx 表示 prompt，ht=(x,y<t)h_t=(x,y_{<t})ht​=(x,y<t​) 是生成第 ttt 个 token 时已经看到的前缀。给定前缀，采样下一个 token 就是做一次动作。序列概率是条件概率的乘积，直到生成 EOS 或达到上限。训练时我们可以逐 token 取对数概率，但这不意味着这些 token 是独立样本：前面的选择决定后续状态是否出现。如果旧策略一直没走进某条解题路径，在已出现的 token 上做局部加权也不会补出那条路径。

    Countdown 的每个 prompt 生成八个回答，验证给出 +1+1+1 或 −1-1−1。优势是回答奖励减去组均值，不再除以组内标准差。举例：三个回答答对，五个答错，组均值为 −0.25-0.25−0.25，两类优势为 1.251.251.25 和 −0.75-0.75−0.75。八个回答的优势加起来是零。可是把这些回答再按某一步是否出现一个有效中间式分组，包含它的前缀可能主要来自答对组，条件平均优势就为正。反过来，错误前缀的条件平均优势可能为负。再加上论文按 token 求平均，较长回答在总体里的权重也与按回答求平均不同。说「已经中心化」时，必须交代是在哪一层求均值。

    算法 1：采集可归因的三组概率

    1. 给每个采样 token 绑定实际生成版本、位置和 token ID。
2. 保存该动作的 log q 和采样端头部集合 H 的 log q。
3. 训练引擎用生成版本回放同一前缀，得到 log r。
4. 训练引擎用当前权重计算 log p；在同一 token 上比较。
5. 保存 e、lag 及其和，同时按优势、位置和版本分组。
6. 在固定探针和新采样响应上分别统计，并保留极端比率。

    这里的头部是采样端的 top-128，不要在训练端重新选一份 top-128 再按名次相减。共享检查点上的配对回放还能避免一种混淆：如果量化和冻结两组模型早已训练到不同分布，直接拿两组末态的平均差比较，观察到的变化既可能来自引擎，也可能来自它们选择了不同前缀。

    7.3 1.7B：重同步恢复了什么，旧前缀又漏掉什么

    论文表 4 的冻结实验里，DLC 第 40 步为 0.6 倍、51.9%，on-policy 准确率 57.6%。三次各同步一次，在第 20、35、36 步；截断权重单用时是 115 倍和 0.5%，加相同阈值的同步后变成 2.6 倍和 36.6%，三次分别复制 2、4、5 次。这个对照已经说明同步本身有很大作用。它还不能说明「中心化加裁剪」在同等复制成本下会好多少，因为不同估计器又改变了触发时间。

    关掉同步的 DLC 三次里有两次准确率跌到初始模型以下，其中回答长度缩短到约 26 token。另一种崩溃出现在加同步的重要性采样中，回答跑到了长度上限。两种方向都可能被旧前缀探针漏掉。论文让当前模型自己采样，沿响应计算它到初始模型的 log-ratio，并把初始模型条件概率低于 10−310^{-3}10−3 的动作贡献加起来，再除以总和。两次不刷新崩溃时这项比例约为 90%，此前最多 14%；完整 DLC 一直不超过 11%。论文所谓「离开支持集」是低概率的操作定义，并非这些动作在旧模型下概率严格为零。分子分母都是带符号的 log-ratio 加总，不是罕见 token 的采样频率；总 KL 很小时也不宜单独解释这个比例。

    一个说明性的覆盖算例：旧策略以 10−510^{-5}10−5 的概率进入某前缀，新策略以 10−210^{-2}10−2 进入。各采 1000 条响应，期望出现次数是 0.01 对 10。在旧采样器的固定探针上几乎没机会看到它，在当前模型上却足以影响评测。真实训练并没有这个虚构前缀，算例只说明「探针没亮红灯」和「新策略没出问题」之间的差别。

    7.4 8B、连续异步与每步时间

    8B 冻结实验每行一次。DLC 为 3.1 倍、49.6%；重要性权重加中心化 2.9 倍、51.8%；on-policy 55.3%。普通中心化虽有 89.1 倍 KL，准确率仍 51.4%。这组数据提醒我，同一可验证任务上答对的比例相近，策略分布仍可能完全不同；反过来，固定探针距离近也不能替代回报评估。

    连续异步的 1.7B 实验里，最大版本差为 4，按 token 平均为 2.85。不同方法每项只跑一次：普通 DLC 为 1.2 倍、55.9%；附带准入机制的 DLC 为 0.8 倍、55.3%；重要性采样为 1.4 倍、52.9%；on-policy 准确率 56.8%。准入变体将 ESS 低的整条响应延后并重新生成，40 步共延后 68 条，论文约计 0.3%，每步 94.2 秒；普通 DLC 为 80.1 秒，重要性采样 43.7 秒。数据支持后续实验，不能据此概括多模型、多集群的吞吐收益。

    在冻结实验，DLC 每步 113.2 秒，对比 on-policy 50.4 秒、带同步的截断权重 52.7 秒。DLC 的参考前向就用了 54.2 秒。论文把其中约 19 秒归到没有参与损失的冗余参考路径。只做减法得到 94.2 秒，仍约为该 on-policy 配置的 1.87 倍；这只是反事实算术，不是实测加速。相比之下，DLC 每次权重复制不超过 1.5 秒，40 步只发生一次。这个环境里省同步次数并不能抵掉参考回放与日志的额外开销。

    8. 局限

    实验范围。 主要证据来自一种算术任务、短截断、一个稠密模型家族、40 步和简单 SGD。动量类优化器还保存梯度历史，复制权重不等于重置偏差在优化器里的积累。长链推理、工具使用或 MoE 路由改变时，旧策略和新策略的覆盖差可能更大，同版本数值差的经验稳定性也未必成立。8B 和连续异步的各行只有一个种子，应视作扩展试验。

    推导范围。 偏差的局部近似要求固定一段时间内的梯度统计，测量没有把续写项估全。较好的拟合说明存在与位移相关的残差，并不能排除本来就随训练变化的梯度曲率。附录 I 用高斯比率推导上下尾概率，若要把它们换成「被裁掉的正负优势 token 比例」，还要知道按优势符号条件化的比率分布。论文图 3 本身就表明两者会关联。

    指标范围。 半数阈值是在特定环境里观察到的经验界线。它既不能控制每个 prompt 的最差覆盖，也不能告诉我们被裁掉的少数样本是否拥有很高价值。旧策略低概率的动作也可能是有用的探索。把低概率贡献占比单独当作失败告警，会误报；只看固定前缀 KL，又会漏报。

    系统结论。 论文按步比较准确率和耗时，未在相同墙钟时间、相同 GPU 预算或相同目标准确率下比较训练进度。额外的参考快照需要怎样存取，在大规模多机上是否把压力转移到内存、网络和批次等待，不能由当前步耗时推出。

    9. 批判性分析：我会怎样做下一轮实验

    9.1 把触发器改成双视角

    旧采样器能回答「当前可用的数据是不是已经很旧」，当前训练器能回答「新策略实际在做什么」。在旧数据流上，我会按生成版本、序列位置、任务和优势符号报告比率的一阶、二阶矩，另外报告 Kish 比例、丢掉的有效 token 比例和被裁掉的优势权重。用 prompt 组做重采样区间，因为一个组的奖励基线是共享的，不能把几百个 token 当成几百次独立试验。这样，如果整体 ESS 还高、但少数有用的高回报动作已被裁掉，也能看到异常。

    在另一条小探针上，让训练端定期用最新权重回答一批留出问题，观察准确率、长度分布、初始策略低概率 token 的真实频率、原始序列 KL，以及归一后低概率贡献。ESS 降低且新策略探针恶化时优先刷新；只有其中一个信号恶化时先用少量新轨迹确认。两条信号对不同的失败模式负责，可以解释是数据老化、质量崩溃，还是有益的分布迁移。运行这条探针也有成本，应记录占用了多少生成时间和训练设备。

    9.2 让每种估计器有相同的刷新机会

    论文最难直接归因的一点是：估计器影响位移，位移影响 ESS，ESS 又影响刷新次数。要拆这三层，可把估计器设为 DLC、仅滞后权重、仅中心化和组合权重四组，每组做冻结、固定频率、适应性触发，再加一组事先在留出种子上校准的等复制预算。固定频率组把数据年龄限制在同一区间，帮助估计单步修正带来的差异；适应性组则衡量每种算法为了保持同等质量需要复制几次。至少跨过数个刷新周期，再比较相同训练时间内的准确率和崩溃频次。

    对于延期再生成，还要统计被延期样本的难度、长度和奖励。若长答或低奖励任务更容易遭延期，进入梯度的分布发生了变化。可以在边界附近抽取少量对照，比较接纳和延期之后的新样本，观察是解决了滞后，还是无意中把训练课程改成了短答案。在报告系统成本时，应加上废弃 token 数、重生成延迟和训练器等数据的时间。

    9.3 给局部理论安排可失败的验证

    我会在一组共享检查点上预先选好投影方向，例如对齐的平均梯度方向和几个独立的随机方向。然后在相同输入上测同版本误差、改权重造成的差、修正后残差，比较其投影及不确定性。加入一项明确干预：只刷新采样权重，不变其他设置，检查滞后相关残差是否如理论下降。若固定前缀上的引擎差也明显跳变，就需要放弃这一轮的「固定偏差」假设，但三分布恒等式仍然成立。

    头部近似也能有更直接的验证。把 top-128 改为几档头部规模，同时记实际尾质量；对少量前缀额外收集更宽的分布，估计尾部 score 偏差。若头部质量已经很高而误差仍集中在几个罕见候选，应调整头部选择或采样规则，而不是盲目扩大所有日志。这样可以把性能花在真正影响梯度的地方。

    9.4 用墙钟预算检验同步策略

    如果目标是把方法放进异步流水线，计时不能只看一次复制有多快。设 TstepT_{\rm step}Tstep​ 是固定训练成本，TreplayT_{\rm replay}Treplay​ 是参考前向的边际成本，TrefreshT_{\rm refresh}Trefresh​ 是一次刷新占用的关键路径时间，fff 是每步平均刷新次数。粗略地，每步成本至少要比较 Tstep+Treplay+fTrefreshT_{\rm step}+T_{\rm replay}+fT_{\rm refresh}Tstep​+Treplay​+fTrefresh​；若还有延期响应，则应另加等待与重生成，并区分可被流水线掩盖的时间和真正阻塞训练器的时间。用同一批数据对比时，不能把已经包含在总步时里的同步成本再加一遍。

    以表 7 的量级说明：DLC 比带同步的重要性采样平均少复制约 2.7 次每 40 步，但每步慢 60.5 秒。若只让这 2.7 次复制差额抵消总步时差，所需差额约为每次 896 秒；这是一个把其他因素假设为不变的成本换算，并非部署预测。原实验复制最多约 1.5 秒，显然离这个假设边界很远。对于实际集群，更有意义的对照是拿同样的墙钟预算，统计消耗了多少训练 token、刷新和重采样分别用掉多少时间，并比较到达目标准确率的分布。若方法在固定步数更稳，却在相同时间里还没走到那个训练区间，就应把这两条结论同时报告。

    10. 复现实验前我会确认的口径

    首先做四格设计：对齐参考、只量化、只冻结、同时量化和冻结。固定 prompt 集、奖励、同一位置的 token ID、抽样概率、组内基线和按 token 的归约。选择配对 on-policy 种子和固定探针，先确认同位置的三个对数概率能闭合，再比较各修正如何改变漂移、剩余偏差和模型自采样的表现。同步前后分开记比率矩和样本生成版本。连续异步实验则另外记准入规则和延期样本量，以免将新的筛选偏差误归到数值误差。

    本笔记实际核对了二项例子的精确期望与 logit 差分、Gaussian 阈值、触发点的矩差和表格的百分点及时间比；没有重新训练模型。若要单测数学定义，可以在很小的词表上令优势为常数，检查精确均值减除后期望为零；再令 p=rp=rp=r 但保留 q≠rq\ne rq=r，检查滞后恰为零而数值差仍在。这两项能检查公式符号、优势的括号位置和参考分母，却不能验证论文报告的训练效果。

    10.1 建议保留的一张对照表

    每个种子固定报告几列：训练步、已用秒数、旧到新的 KL 和固定前缀上的模型间 KL、比率矩、丢弃与重新生成的响应数，以及当前策略的答题准确率。前两种 KL 的方向和探针不同，应有各自列名；另报噪声底线的原始数值，避免只剩无量纲倍数。旧到新的 KL 用采样时版本的路径来估，当前策略的罕见 token 贡献则必须用当前策略自己生成的回答。这样同一日志可以回答「比率什么时候变坏」和「策略是否真的开始答错」两件事。

    跨配置比较时，我会同时给固定步数和固定耗时的图，给同一 prompt 池上的配对差值及不确定区间。若某个种子提前崩溃，把它作为结果保留，不能只对活下来的曲线取平均。还要区分刷新前后一批样本实际携带的版本；若同步后还有旧请求尚未出队，所谓「刷新后的 ESS」不应把它们与新版本混成一个数。完成这些对照之后，才有条件讨论阈值该不该从 0.5 调整，或改成能随着任务、代价与版本距离变化的策略。

    11. 结论

    DLC 让我重新看待训推差异：先确认同一个动作究竟在哪份策略和引擎下生成，再问什么能在这一批数据上校正，什么必须通过改变下一批的来源解决。参考前向把版本差和数值差分开；裁剪滞后权重和减去其均值各处理不同的局部项；重同步才把未来的前缀重新交给更接近当前的策略。论文的 1.7B 冻结对照支持这一解释，同时也给出固定前缀探针漏报、参考前向昂贵的反例。下一步最有价值的问题是：在相同时间和质量目标下，这些额外信息与刷新决策是否仍然划算。
