    AutoMaster 阅读笔记：让同一个教师示范得更好

    笔记日期： 2026-11-23 · 作者： Zhongzhu Zhou
    论文题名： AutoMaster: Autonomous Post-Training by Making the Same Model a Better Teacher
    论文作者： Guoxin Chen、Shuang Sun、Fanzhe Meng、Xinyu Tang、Ruihua Song、Wayne Xin Zhao
    arXiv： 2611.26510 · 版本与日期： v2，2026-11-20；首次提交 2026-11-19

    1. 我最看重的贡献：成功不等于值得模仿

    做对一道题的过程，未必是好的教材。搜索智能体可能猜了很多没有依据的线索，最后碰巧找到答案；数值程序虽然通过指定误差阈值，解释中却夸大了收敛阶数。如果把所有成功轨迹直接当作监督微调数据，学生会同时学到有效动作和这些不可靠习惯。

    AutoMaster 选择在生成示范之前干预。教师模型的参数不变，把具有适用条件和具体步骤的自然语言技能附加到系统提示里，让教师更经常地展示需要的行为。然后再挑选示范训练学生。这里有两个层次：Skill-FT 是技能引导生成加监督微调的学习流程；AutoMaster 是负责分析轨迹、设计技能、试验、选数据并读取学生反馈的智能体。

    图 1：根据原文第 3 节自绘。上方改变固定教师产生什么轨迹；下方检验学生能否学会。每轮学生都从初始权重重新训练，累积的是实验经验。

    我觉得论文最有价值的不是「给教师一个提示会更好」这个直觉，而是三个相互关联的结果。相同教师和 512 条示范预算下，改变示范行为还有提升空间；技能引导和数据选择可能互相补足，单独用一个部件甚至不如普通 SFT；训练时保留技能原文，尽管测试时不提供技能，六个设置的均值仍然都比删除技能更高。最后一点值得认真区分「减少提示分布差异」与「保留有解释力的训练上下文」。

    但结论也有边界。9B 模型的配对证据更一致；4B 在 Search 和 Doc2Repo 上的增益区间跨过零。外循环会反复查看评测分数和轨迹，并据此选最终检查点，因此这些结果尚不能独立回答在完全没碰过的最终测试集上能保留多少收益。

    我读的是 v2 全部 21 页，包括附录 A 的训练、评测、消融与配对区间，以及附录 B 的四份技能示例。下文的概率推导、小算例和数值复算用于解释论文，不代表重新训练模型或重跑基准。引用原图、重绘数据和我提出的分析会分别说明。

    2. 前置知识：轨迹、成功筛选与监督信号

    2.1 成功标签究竟筛掉了什么

    设任务为 xxx，基础系统提示为 ppp，技能文本为 sss。在第 ttt 步，教师根据历史 hth_tht​ 产生动作或消息 ata_tat​，环境返回 oto_tot​。完整轨迹 τ\tauτ 包含推理、工具调用、工具结果和最终回答。把轨迹概率展开，可以写成

    qT(τ∣x,p,s)=∏t=1TπT(at∣ht,p⊕s)P(ot∣ht,at).(1)q_T(\tau\mid x,p,s)=\prod_{t=1}^{T}\pi_T(a_t\mid h_t,p\oplus s)P(o_t\mid h_t,a_t). \tag{1}qT​(τ∣x,p,s)=t=1∏T​πT​(at​∣ht​,p⊕s)P(ot​∣ht​,at​).(1)

    πT\pi_TπT​ 是固定教师，PPP 是环境转移，⊕\oplus⊕ 表示文本拼接。这是我对原文 rollout 记号的展开，用于说明干预点：技能改变教师的条件决策，而不直接改变环境。工具观察是上下文，不能因为写进轨迹就把它当作教师自己生成、需要预测的输出。

    设 R(τ)R(\tau)R(τ) 是成功指示变量。只保留成功轨迹时，采样分布变为

    qsucc(τ∣x)=qT(τ∣x)1{R(τ)=1}Pr⁡qT(R=1∣x).(2)q_{\mathrm{succ}}(\tau\mid x)=\frac{q_T(\tau\mid x)\mathbf{1}\{R(\tau)=1\}}{\Pr_{q_T}(R=1\mid x)}. \tag{2}qsucc​(τ∣x)=PrqT​​(R=1∣x)qT​(τ∣x)1{R(τ)=1}​.(2)

    分母必须大于零。这个条件分布确实去除了失败，但没有区分「有根据地成功」和「侥幸成功」。如果验收器只看最终答案，那么不必要的反复搜索、错误但未影响输出的解释、恰好未触发的边界错误，都可能留在成功集合里。再采更多成功轨迹，主要减少抽样误差，不会自动修复筛选标准没有观察到的行为偏差。

    图 2：原创说明性分布，不是论文实验。两组成功率都是 80%，但可靠成功占全部轨迹的比例从 10% 变成 40%；在成功集合内部，则从 12.5% 升至 50%。

    这个例子解释了为什么「教师没变强」与「学生学得更好」并不矛盾。教师总体答对多少，与它向学生示范了什么，是两个变量。不过，展示更多检查动作也不必然更好：无信息量的检查会增加 token 和延迟。如果把严谨行为简单定义为「说了更多验证的话」，反而可能教出新的表演性习惯。

    2.2 不计入损失，也会影响梯度

    附录 A.3 明确：assistant 的推理、回复和工具调用参与交叉熵；system、user 和 tool 消息只作为上下文，不参与损失。用 mitm_{it}mit​ 表示第 iii 条示范中第 ttt 个 token 是否受监督，目标为 yity_{it}yit​，前缀为 citc_{it}cit​，则

    L(θ;D)=−1M∑i,tmitlog⁡πθ(yit∣cit),M=∑i,tmit.(3)\mathcal L(\theta;D)=-\frac{1}{M}\sum_{i,t}m_{it}\log\pi_\theta(y_{it}\mid c_{it}),\qquad M=\sum_{i,t}m_{it}. \tag{3}L(θ;D)=−M1​i,t∑​mit​logπθ​(yit​∣cit​),M=i,t∑​mit​.(3)

    这个式子按受监督 token 归一化。技能虽然在 system 提示中，不需要作为目标被预测，却能影响之后的注意力、隐状态和输出分布。因此「技能 token 不算 loss」不能推出「保留技能对训练没有影响」。

    以单个 token 的 logits zzz 为例，目标下标为 yyy，交叉熵为 −zy+log⁡∑jezj-z_y+\log\sum_j e^{z_j}−zy​+log∑j​ezj​。逐项求导得到

    ∂ℓ∂zj=πθ(j∣c)−1{j=y}.(4)\frac{\partial\ell}{\partial z_j}=\pi_\theta(j\mid c)-\mathbf{1}\{j=y\}. \tag{4}∂zj​∂ℓ​=πθ​(j∣c)−1{j=y}.(4)

    保持 yyy 不变而改变前缀 ccc，概率项和网络对参数的 Jacobian 都会变化。Keep 和 Remove 虽然监督相同的输出，梯度并不相同。这只能解释为什么实验结果可能不同，尚不能预先保证哪个条件在无技能测试时泛化更好。

    另一个容易忽略的点是长度。按 token 归一化时，一条两万 token 的示范通常比两千 token 的示范贡献更多目标项。相同 512 条轨迹，不等于相同受监督 token 数，也不等于相同计算成本。论文控制了条数和 SFT 配方；若要进一步证明等计算优势，还需要长度、截断和实际训练工作量的记录。

    3. Skill-FT：先改变教师会怎样行动

    原文式（1）可以直接写为

    τ∼Rollout⁡(πT,x;p⊕s).(5)\tau\sim\operatorname{Rollout}(\pi_T,x;p\oplus s). \tag{5}τ∼Rollout(πT​,x;p⊕s).(5)

    技能可以是行为原则、操作流程，也可以包含领域知识；可跨任务共享，可仅分配给某类任务，还可组合使用。它通过系统提示影响教师执行。教师本身没有在这个过程中更新权重。得到轨迹后，再按任务结果和行为价值筛选 512 条，用原始提示连同技能一起进行学生 SFT。已经具有有效行为的无技能轨迹也允许被选入。

    例如，一条数值技能不应只说「请认真验证」。更有用的内容是：先确定误差定义和接受阈值，用独立参考建立比较，确保失败真的进入断言或错误分支；失败后保留原始输入和阈值，诊断问题，而不是换成容易通过的样本。搜索技能则关注停滞时哪个限制还只是猜测，以及下一次查询能够推翻哪个假设。两类技能各有适用条件，混成一份通用长清单未必有效。

    为了区分方法里的几个变量，我用一个示意分布表示训练数据来源：

    qD(τ,x)∝∑sws(x)qT(τ∣x,p,s)A(τ,x,s).(6)q_D(\tau,x)\propto\sum_s w_s(x)q_T(\tau\mid x,p,s)A(\tau,x,s). \tag{6}qD​(τ,x)∝s∑​ws​(x)qT​(τ∣x,p,s)A(τ,x,s).(6)

    ws(x)w_s(x)ws​(x) 表示技能与任务的分配，AAA 表示选择权重或接纳条件。这个式子是我的分析模型，不是作者提出的数值选择函数。它提醒我，最终数据同时受任务构成、教师生成行为、轨迹筛选三项影响。看见学生提高，不能直接把全部收益归因于技能措辞。

    图 3：原论文 Figure 2，取自 v2 第 4 页，Chen 等，CC BY 4.0。内循环设计和筛选示范；外循环从初始权重训练学生，再把分数和轨迹交回下一轮。

    为什么固定教师值得强调？实际团队可能已经选定了可调用的模型，却没有预算换一个更强教师。论文说明，在这个约束下，示范生成方式仍有空间。它没有证明在相同总成本下必然优于换教师、增加采样、过程奖励筛选等所有替代方案。那些选择会改变别的成本和能力，应当单独对比。

    这里最关键的设计取舍，是把「教师能否按要求示范」和「学生能否学会」分开。技能让教师展示复杂过程，不意味着 4B 学生能从少量长轨迹里吸收这个过程。更短、更明确、有适用条件的示范可能更容易学，也可能覆盖不足。先做小规模 pilot，只检验技能对教师的影响；训练后评估，才检验示范对学生的价值。

    失败边界也很具体。错误技能能系统性地产生错误教材；范围过宽的技能会把必要检查变成无用开销；过于贴合某个训练任务的提示可能携带答案线索，而不是可迁移能力。即使教师输出更像严谨分析，也必须回到行为结果和学生表现检验其实际价值。

    4. 两个循环的算法与状态

    算法 1：开发技能并组成示范集

    下面按原文第 3.2 节整理。作者没有规定每个 pilot 必须重复几次，也没有给所有选择决定定义一个统一标量评分函数。

    Input: fixed task pool X, fixed teacher T, initial student traces,
       experiment history H, demonstration budget N = 512
1. Read tasks and unguided teacher/student trajectories.
2. Identify a harmful habit or a useful underrepresented behavior.
3. Write a skill with explicit scope and a discriminating procedure.
4. Assign the skill to relevant task subsets.
5. Run pilot teacher trajectories with the assigned skills.
6. Inspect behavior, task outcomes, and new failure modes.
7. Revise wording or scope; repeat pilots when evidence warrants it.
8. Scale promising interventions within the fixed task pool.
9. Select N demonstrations using outcomes and observed behaviors;
   allow useful unguided demonstrations when appropriate.
10. Save task IDs, original prompts, trajectories, and their lineage.
Output: D_r and linked intervention records

    第 3、4 步不能分开理解。同一句规则在适当场景是正确知识，在不适当场景可能制造错误。后文脚本权限的例子正是如此：直接执行与通过解释器执行，需要的条件不同。简单地规定「没有 execute bit 就补上」，会把无关修改当成良好行为。

    第 9 步也不能只看「干净」。如果容易验证的简单任务占满数据，学生可能更擅长局部检查，却更不擅长困难规划。任务匹配消融能控制任务身份，但还控制不了示范长度、正确程度以及筛选前花了多少采样成本。这些变量在解读实验时需要继续保留。

    算法 2：用学生反馈搜索下一轮干预

    Input: initial student weights theta_0, task pool X,
       teacher T, five-round budget, experiment history H
1. For r = 1,...,5:
2.     D_r <- Algorithm 1(X, T, H), with 512 demonstrations.
3.     theta_r <- full-parameter SFT(theta_0, D_r).
4.     Evaluate the final-epoch checkpoint without generated skills.
5.     Record scores, task trajectories, checkpoint, D_r, and skills.
6.     Add this evidence to H for the next experimental decision.
7. Select a checkpoint using accumulated evaluation feedback.
Output: selected checkpoint and final experiment report

    最需要记住的是原文式（2）：

    θr=SFT⁡(θ0,Dr),r=1,…,5.(7)\theta_r=\operatorname{SFT}(\theta_0,D_r),\qquad r=1,\ldots,5. \tag{7}θr​=SFT(θ0​,Dr​),r=1,…,5.(7)

    每次右边都是 θ0\theta_0θ0​，不是 θr−1\theta_{r-1}θr−1​。这让不同数据干预更容易比较，代价是反复训练。如果从上一轮学生继续训练，后面的变化会同时混入旧数据累积、训练路径和额外更新预算，那已经是另一种算法。不能把图中的五轮进展解释为同一学生连续学习了五次。

    系统长期记住的是实验历史。一个行为没有出现在学生中，至少有三种原因：教师没有展示；教师展示了但示范没被选入；示范进了训练集但学生没有吸收。前者指向技能设计，中间指向数据选择，后者可能涉及容量、覆盖或训练预算。能沿记录区分这三种情况，是 AutoMaster 比只有分数表更有意思的地方。

    5. 系统结构：让数据和结果能追溯

    论文描述的基础设施把任务、教师生成、学生训练、模型评估连接起来。编排智能体在 Docker 容器里通过 MCP 读取数据、提交 rollout 和 SFT；教师通过 API 调用，学生由 SGLang 提供推理；任务工具和验证器放在隔离容器中执行。这里解释的是论文中的系统设计，没有展开仓库内部实现。

    图 4：原论文 Figure 3，取自 v2 第 5 页，Chen 等，CC BY 4.0。共享存储减少检查点的中转复制；关联记录把学生表现追溯到数据和技能。

    执行控制器在 SFT 完成、检查点可用之后安排评估。训练集群和评估集群共享检查点存储，评估服务可以直接加载。系统记录阶段进度，推理 worker 失败时能够恢复评估，避免为了一个服务故障重跑 SFT。自主实验需要这些机制，否则「技能不好」和「机器没跑完」很容易被混为一谈。

    我会把最小实验记录理解为 (sr,Dr,θr,Er)(s_r,D_r,\theta_r,E_r)(sr​,Dr​,θr​,Er​)：技能、真正使用的数据、真正评估的检查点，以及任务级分数与轨迹。如果只有技能和分数，中间缺少实际选入的数据，后续诊断就可能把从未被训练的技能误当成学习失败。如果只有总体分数，智能体又无法区分某个习惯是减少了还是换了一种失败方式。

    这套系统有实用价值，也有部署门槛。共享存储、训练和推理集群、沙箱并不是零成本条件。恢复机制还要区分同一次评估的续跑与新增随机评估；如果只重试表现差的任务，最后的平均值就会改变含义。论文介绍了工程流程，但没有给完整的端到端成本表，因而不能据此宣称它在小规模任务上一定划算。

    6. 先固定实验口径，再看分数

    每个方向随机抽取 1,000 个训练任务，所有方法共用固定池。Terminal 的来源是 CalibForge，Search 是 FORT-Searcher，SWE 是 DeNovoSWE。评估分别采用 Terminal-Bench 2.1 的 89 个任务、Traverse 发布的 BrowseComp-Lite 185 题，以及 Doc2Repo 的 50 个仓库。SWE 评测关闭搜索工具。这里的 Search 结果不能扩大为完整 BrowseComp 的结果。

    学生是 Qwen3.5-4B 和 Qwen3.5-9B。作者报告编排智能体使用 Codex 中的 GPT-6 Astra，xhigh reasoning effort；教师为 DeepSeek-V4-Pro-Preview，high reasoning effort。这些是论文的实验配置，不意味着换成更便宜的编排模型仍会设计出同样质量的技能。

    SFT 统一用 512 条轨迹、3 个 epoch、global batch size 32、全参数训练，最大序列长度 131,072。附录 A.3 还给出 Megatron Adam，学习率从 10−510^{-5}10−5 按 cosine 降到 10−610^{-6}10−6，warmup 5%，β1=0.9\beta_1=0.9β1​=0.9、β2=0.999\beta_2=0.999β2​=0.999、weight decay 为零、梯度裁剪 1.0、bfloat16。比较方法共享这些配方。

    如果 global batch 的单位按轨迹计算，并忽略额外 packing 和不完整 batch 的细节，则一次训练名义更新数为

    Unominal=512×332=48.(8)U_{\mathrm{nominal}}=\frac{512\times3}{32}=48. \tag{8}Unominal​=32512×3​=48.(8)

    五次独立训练就是 240 个这样的名义更新。这只是根据表格做的账面估算，不是实际 optimizer 日志。长轨迹的 token 数、padding、packing 和截断都会改变工作量。同样更新数也无法自动保证相同 FLOPs。

    教师 temperature 和 top-p 均为 1.0。Terminal/SWE 单次回复最多 16,384 token，Search 为 8,192；任务步数上限分别是 500、400、300。教师 Terminal 时间上限 1 小时，SWE 3 小时，Search 不设总任务时限。评测统一用 temperature 1.0、top-p 0.95、每次回复最多 65,500 token、每任务最多 600 步；Terminal 上限 3 小时，SWE 4 小时，Search 无总时限。

    上限不是平均消耗。不能把 600 步乘以单次最大回复量，称为每题实际成本。但这些宽松预算说明，最终还需要报告真实动作数和延迟分布。若学生学会了更多验证，同时把每题时间拉长很多，准确率提高和产品可用性就可能出现取舍。论文的分数表本身尚未回答这一点。

    8. 消融：选择和引导怎样互补

    去掉技能引导时，智能体仍然自主选择无技能教师轨迹；去掉数据选择时，智能体仍设计技能，但在固定随机任务子集上使用，省去自主轨迹筛选。它们仍保留自主试验，以及相同教师、任务池、示范条数和 SFT 配方。因而这些不是「完全没有 AutoMaster」的简单开关。

    8.1 任务匹配控制了什么，没控制什么

    Task-Matched SFT 保持完整方法最后选中的任务 ID 和每任务条数，用同一教师的无技能轨迹替代。AutoMaster 六项均值仍高 1.08–10.11 个百分点。因此，收益不能仅由「恰好选了更好的任务身份和数量」解释。

    但附录 A.5 说明，为了保持任务匹配，无技能一侧保留了失败轨迹。Terminal 4B 的 512 对中，106 对是无技能失败、有技能成功，406 对双方都成功；Terminal 9B 对应为 100 和 412，Search 4B 为 45 和 467，Search 9B 为 64 和 448。双方成功比例为

    原文 Figure 5 的作用，是让抽象的「好行为」变成可讨论的动作。不过它们是挑出的案例，并不是各种失败模式在全语料中的频率估计。我把它们当作潜在机制的证据，不拿几个成功案例代替总体因果分析。

    9.1 数值案例：通过阈值不能证明四阶

    无技能教师的 Poisson 求解器满足指定误差阈值，却声称具有四阶精度。论文打印的误差在网格 32 时约为 1.36×10−31.36\times10^{-3}1.36×10−3，网格 64 时约为 3.31×10−43.31\times10^{-4}3.31×10−4。若进入渐近区间且 E(h)≈ChpE(h)\approx Ch^pE(h)≈Chp，网格间距减半后，有

    E(h)E(h/2)≈2p,p≈log⁡(E(h)/E(h/2))log⁡2≈2.04.(12)\frac{E(h)}{E(h/2)}\approx2^p,\qquad p\approx\frac{\log(E(h)/E(h/2))}{\log2}\approx2.04. \tag{12}E(h/2)E(h)​≈2p,p≈log2log(E(h)/E(h/2))​≈2.04.(12)

    这更接近二阶。一次误差小于 5×10−45\times10^{-4}5×10−4，只验证该配置的验收阈值，没有验证四阶收敛率。技能引导的轨迹使用独立检查，改为九点格式，再通过不同网格的直接求解检验四阶行为。这里我只复算了论文打印的误差比例，没有执行作者的求解器。

    这里有一个需要保留的克制：四阶并不是原任务必需条件。一个诚实报告二阶、满足阈值且更便宜的方案仍可能是合格答案。技能应该让结论与证据一致，而不是擅自给任务添加更高标准。正确性、收敛阶数、稳定性、运行时间，各自需要不同证据。

    9.2 搜索案例：真正的转向要改变假设

    两条搜索轨迹最后都找到了同一集电视剧。无技能教师先猜奖项名称，之后反复检索；有技能轨迹先从集数与导演记录识别人，再核实教育和奖项线索。差异是获取证据的顺序，不是技能暗中提供了最终答案。

    问题常出在把猜测写进查询限制。越查越像有证据，实际只是同一假设筛出来的内容。有效转向需要删除尚未证实的限制，找另一种能独立识别候选的关系，并检验旧候选解释不了的线索。只把查询换个措辞，保留同样的猜测限制，未必产生新信息。论文的例子说明了这种机制，但没有统计完整数据集中真正转向的比例。

    9.3 UTF-16 案例：先判断是程序错还是测试错

    题目要求按 UTF-16BE 升序排列键，比较 U+FB33 与 emoji U+1F602。emoji 的首个 surrogate code unit 是 D83D，所以应在 FB33 前面。错误自测却把原键换成 U+05D3 与 U+05BC 的序列，它的第一个 code unit 05D3 又在 D83D 前面：

    05D3<D83D<FB33.(13)\mathtt{05D3}<\mathtt{D83D}<\mathtt{FB33}. \tag{13}05D3<D83D<FB33.(13)

    因此两个输入的正确相对顺序不同。无技能教师为了满足错误期望而反转全局排序，破坏规范；有技能教师追查输入编码，修正自测并保留升序，论文报告通过 38/38 测试，对照为 32/38。这是原论文案例结果，不是我对仓库运行得到的结果。

    这个案例的教材价值，是失败后先验证 oracle 的含义，再改实现或期望值。否则，一条自测通过的证据可能来自同时改错程序和测试。真正有迁移价值的行为，应当能在新任务中识别这种冲突，而不仅记住「不要改排序方向」这一条局部经验。

    Keep 条件保留生成示范时用的技能；Remove 只删技能文本，监督的推理、回复、工具调用完全相同。两个条件在测试时都没有生成技能。原文报告 Keep 比 Remove 高：Terminal 4B/9B 为 3.00/3.75 个百分点，Search 为 3.60/2.34，SWE 为 4.01/2.15。

    10.1 条件变了，学习问题也变了

    把完整 token 掩码暂时省略，可以把两种目标写为

    LK=−EDlog⁡πθ(y∣x,s),LR=−EDlog⁡πθ(y∣x).(14)\mathcal L_K=-\mathbb E_D\log\pi_\theta(y\mid x,s),\qquad \mathcal L_R=-\mathbb E_D\log\pi_\theta(y\mid x). \tag{14}LK​=−ED​logπθ​(y∣x,s),LR​=−ED​logπθ​(y∣x).(14)

    二者共享 (x,s,y)(x,s,y)(x,s,y) 对应的数据和输出，却不共享可见信息。假设能做理想的条件概率拟合，隐藏技能时需要边缘化：

    pD(y∣x)=∑spD(s∣x)pD(y∣x,s).(15)p_D(y\mid x)=\sum_s p_D(s\mid x)p_D(y\mid x,s). \tag{15}pD​(y∣x)=s∑​pD​(s∣x)pD​(y∣x,s).(15)

    如果不同技能解释不同的正确动作，不提供技能就可能把多个策略混在一个更难学习的条件分布里。一般的条件熵恒等式为

    HD(Y∣X)−HD(Y∣X,S)=ID(Y;S∣X)≥0.(16)H_D(Y\mid X)-H_D(Y\mid X,S)=I_D(Y;S\mid X)\ge0. \tag{16}HD​(Y∣X)−HD​(Y∣X,S)=ID​(Y;S∣X)≥0.(16)

    它说明额外条件信息可以降低目标的不确定性。但这个恒等式不是无技能泛化定理。 测试时 sss 消失，学生也可能过度依赖它。论文的实验证据是：在这些具体设置里，保留上下文的收益超过了依赖风险，体现为六项均值更高。不能把这个现象普遍化为「训练时提示越丰富越好」。

    10.2 一个更直接的解释：别把答案的前提删掉

    原文 Figure 7 有两种示范。脚本通过 Python 解释器调用，教师根据技能区分直接执行和解释器执行，从而避免无必要的权限修改。表达式解析案例则引用技能里的 grammar，推导幂和一元负号的绑定规则。删除提示里的技能，却保留输出中「根据技能」的推理，相当于让教材保留解答、删去部分已知条件。

    Keep 可能帮助学生学会条件规则，也可能主要修复输入输出的语义连贯性，还可能通过更长上下文改变注意力和梯度。论文的案例使前两种解释合理，但没有把它们分离。因此我不会把分数提升直接称为已证明「推理内化」的唯一机制。

    一个更清楚的实验应加入 coherent Remove：删技能时，也把仅依赖技能指代的语句改写连贯，保留实际动作；再加等长无关提示、技能释义和随机删除技能的条件。若修复悬空指代之后 Keep 仍有明显优势，对「显式条件帮助学习程序」的证据就更强。

    10.3 用条件不成立的题测试是否真的学会

    训练样本里某技能一直适用，学生有可能把它学成无条件习惯。比如直接执行时缺权限与通过解释器执行是不同情境；正确做法不应都变成 chmod。检验内化能力时，应专门放入技能前提不成立的反例，观察模型是否抑制无关动作。

    领域技能还有知识含量。grammar 不只是通用的思考态度，它给了形式规则。如果任务本来没有这些规则，保留它可能提高知识供给；若规则与目标规范冲突，又会造成系统错误。需要分别检查「学会新知识」「学会何时使用规则」「仅仅依赖熟悉措辞」三个层面，而不能只看无技能测试平均分。

    11. 五轮搜索：改进来自探索，也伴随选择偏差

    原文 Figure 8 中，各设置最高均值出现在第 2 到第 4 轮，相比第一轮高 2.16–4.87 个百分点。BrowseComp 9B 前三轮在约 49% 附近，第四轮才到 51.53%。这说明一次不明显的试验不代表方向没有空间，但也不意味着每增加一轮都会更好。

    9B 在三个方向的每一轮均值都超过 Vanilla；4B 只有 Terminal 在五轮中都超过。学生容量可能影响复杂示范能否被吸收，这是合理假说，但两个大小、同一模型家族还不足以建立可靠的规模规律。

    11.1 最后只用 512 条，不等于开发过程便宜

    把总开发成本拆开更清楚：

    Cdev=Cinitial+∑r=15(Cagent,r+Cpilot,r+Cbatch,r+CSFT,r+Ceval,r).(17)C_{\mathrm{dev}}=C_{\mathrm{initial}}+\sum_{r=1}^{5}\left(C_{\mathrm{agent},r}+C_{\mathrm{pilot},r}+C_{\mathrm{batch},r}+C_{\mathrm{SFT},r}+C_{\mathrm{eval},r}\right). \tag{17}Cdev​=Cinitial​+r=1∑5​(Cagent,r​+Cpilot,r​+Cbatch,r​+CSFT,r​+Ceval,r​).(17)

    固定最终示范条数只控制这张账单的一部分。找到那 512 条之前，智能体可能试过大量技能和失败轨迹。公平比较可以按美元、教师 token、GPU 时间或总开发时间等不同预算约束进行；不同约束下最好的方法也可能不同。

    举个明确的说明性算例：512 条示范平均每条 12,000 个受监督 token，3 个 epoch 大约暴露 1,843.2 万 token；平均长度若翻到 24,000，暴露量也翻倍。这里的长度是假设，不是论文数据。system 和工具上下文还会产生计算开销，但未必增加监督 token。因而应该分别记录输入 token、输出 token、有效监督 token 和截断比例。

    11.2 选最好的一轮，不能忽略怎么选的

    可以把一轮观察分数写成 V^r=Vr+ϵr\widehat V_r=V_r+\epsilon_rVr​=Vr​+ϵr​。取 r∗=arg⁡max⁡rV^rr^*=\arg\max_r\widehat V_rr∗=argmaxr​Vr​ 时，被选中的可能同时包含真正改进和有利噪声。AutoMaster 还会读旧评测轨迹来设计新干预，所以问题比从五个独立噪声数里取最大值更复杂：它可能逐渐适应开发时反复出现的任务特征。

    这不是已发现某个具体泄漏事件，而是实验设计的限制。更多搜索可以找到更好的干预，同时也更需要独立终测。对最终检查点的旧任务分数做配对 bootstrap，只分析这层任务差异，不能代替对整个「开发、选择、终测」流程的验证。

    12. 局限与失效边界

    评测反馈参与开发。 附录 A.4 说，基准评测的分数和轨迹供后续试验使用，最后再据累计反馈选检查点。结果对这个协议有意义，但尚未独立隔离对未触达任务的泛化。这里指出的是适应性评测问题，并没有证实训练数据里存在某道测试题。

    不确定性没有覆盖全部随机来源。 三次评测是同检查点重复；任务 bootstrap 条件于已记录数据。重新训练、重新生成技能库、重新做五轮搜索，可能再引入波动。4B 两个区间跨零，六个逐项区间也不是同时保证。

    行为证据主要来自示例。 Figure 5 和附录 B 很具体，却没有盲标随机轨迹中好行为的出现率、无用动作的增加率和技能退化率。模型也可能学会更常说「我验证过」，而不是运行能否定当前假设的检查。

    任务匹配仍混有质量差异。 无技能匹配示范里保留失败，完整方法更多成功。因此它排除了仅由任务身份解释收益，却没有把「更多正确示范」和「相同成功下过程更好」彻底分开。

    模型和场景覆盖有限。 一个教师、一个编排配置、同系列两个学生大小、三个任务域，还不足以说明跨教师、跨模型和短上下文部署的表现。更强教师可能原本就经常展示目标行为；更小学生可能吸收不了长程序式示范。

    计算与时延口径不足。 相同条数和配方不保证总搜索计算、实际训练 token、教师采样量或测试动作数相同。目前最稳妥的说法是指定基线下分数改善，不能直接扩展为等总成本最优。

    技能带有知识，也可能带错知识。 grammar 等技能提供领域规则。它的贡献可能同时来自知识注入和策略改善；范围错误时也会教坏学生。只统计技能适用的任务，难以检验模型是否学会适用条件。

    13. 独立批判性分析：我会优先补哪些实验

    13.1 把开发反馈和最终成绩分开

    我首先会用三层数据：训练池用于生成示范，开发集用于五轮技能搜索，封存测试集只在选定检查点后使用一次。最终任务的轨迹在选点完成前不能被编排智能体读取。目的不是禁止有用反馈，而是测量这些反馈在没有直接指导过的任务上能带来多少收益。

    如果样本很少，可以考虑交叉拟合：每一折的评测对象由没看过这一折的过程开发出来。这样成本更高，却比把重复使用的任务分数 bootstrap 成一个最终泛化数字更清楚。搜索预算和选点规则也应在打开终测之前固定。

    还应独立重复整个搜索，而不只是对同一结果多评几次。若三次完整 AutoMaster 运行生成了不同技能与数据，却都在封存集提高，证据比一个被充分开发的检查点更有说服力。需要把「开发过程的可重复性」作为单独结果报告。

    13.2 让行为成为能测量的中间变量

    先定义可观察行为：数值参考是否独立，失败是否真的触发分支，搜索是否移除了未证实限制，排序期望是否按真实编码推导。随机抽取成功和失败轨迹，由不知道方法标签的标注者评价，既统计有效动作，也统计多余动作和退化。

    随后在相同任务、相同成功结果和相近 token 预算下改变技能引导。特别是双方都成功的匹配语料，适合回答「同样答对，过程更好是否更值得学」。SWE 的分析仍应按仓库分组，因为同一个实现会让许多测试一起变化。行为指标最终应预测新任务可靠性，不能只是迎合评审模型喜欢的书面风格。

    如果技能使轨迹更长，可以另外给一组同 token 预算的无技能样本。否则我们无法区分「更好的步骤」和「只是多花了时间」。这并不是否定长轨迹，而是让读者知道收益究竟换来了什么。

    13.3 把 Keep 的连贯性收益与规则学习分离

    我会保留原始 Keep／Remove，同时增加连贯改写的 Remove、等长无关上下文、规则释义和随机技能删除。测试端加入无技能、同义技能、错误技能，以及规则前提不成立的题。这样能观察学生是记住措辞，还是学会何时调用一个程序。

    还可提出一个诊断性训练变体：以概率 ρ\rhoρ 保留技能，其余样本改为语义连贯的无技能轨迹，扫描 ρ\rhoρ。如果少量无技能训练既保留收益，又减少无关规则激活，就更有部署价值。但这只是我提出的实验，不能写成已经发现的改进。

    重要的是保护被比较的目标：只改与技能指代有关的语句，尽量不改变实际动作和可验证结论。否则所谓 coherent Remove 又会成为另一套重新优化的数据，无法回答原来的机制问题。

    13.4 用完整预算比较自主搜索的价值

    在同总开发预算下，与更多无技能成功采样、固定技能库、随机技能分配、人写的有范围技能做比较。记录失败 pilot、教师输入输出 token、SFT token、评测调用、编排模型调用和总时间，并区分复用已有基础设施和新增任务域的边际成本。

    如果主要成本来自多次全参数训练，优化编排提示的 token 费用可能不是关键；如果主要成本来自高价教师长轨迹，则更精确的 pilot 和选择可能更值钱。没有账单分解，小团队很难判断它适合一次性的 4B 任务，还是适合长期复用的大规模后训练系统。

    我对论文的积极判断集中在干预位置：应该优化教师展示什么，而不只是过滤最后答对了什么。保留意见则集中在证据：需要独立终测、行为测量、成功匹配和成本控制，才能知道这种数据开发能力有多可迁移。

    14. 复现要点与本次复算范围

    按论文重做实验时，先固定训练／开发／测试划分、教师版本、学生初始检查点、harness、基础提示、监督掩码和五轮选点协议。每条轨迹保留原始系统提示，记录技能及其适用范围、是否无技能生成、任务结果和选择来源。真正进入 SFT 的数据，应与真正评估的检查点关联起来。

    训练按附录 A.3，评测按 A.4，并区分第三个 epoch 检查点和跨五轮选出的最终检查点。Terminal／Search 统计任务准确率，SWE 统计仓库平均测试通过率。失败、超时和恢复要有一致规则；不要只对不满意结果增加随机重试。SWE 的区间以仓库为单位，保留方法间的任务对应关系。

    若要更强的可重复证据，应独立重复完整技能开发与 SFT，再使用未参与开发的测试。发布语料长度、截断比例和 token 分布，才能解释相同 512 条的比较。在较短上下文部署时，还应检查模型是否依赖训练轨迹中只有超长历史才能提供的证据。

    本次独立复算包括：已显示均值与增益的关系、双方成功比例、48 个名义更新的账面估算、误差比对应的收敛阶数、UTF-16 code unit 次序，以及小规模 softmax 梯度有限差分。它们检查的是解释中的数学与算术，不是模型训练结果、基准性能或作者软件的正确性。

    15. 结论

    AutoMaster 让我重新关注一个后训练问题：教师的价值不只体现在能力上，还体现在它愿意向学生展示什么过程。自然语言技能可以在数据生成阶段改变行为，数据选择决定哪些行为被学习；训练时保留技能上下文，有时比机械地让提示更像测试条件更有效。

    我会把论文作为一个值得实测的数据开发方案，而不是「技能必然带来通用自我提升」的证据。9B 在作者协议下有更一致的配对提升，4B 的小增益和反复使用的评测反馈则要求保留判断。最值得继续做的，是在独立终测和完整成本账单下，检验更好的示范过程是否真的转化成更可靠的学生。
